# The doors are thin: a route file imports no repository and no provider client

**Status.** Written against `s10/wave-2` as folded (`33d74c8fa`, 30 September 2026: the observe and secure lanes are in it, so the moves are rebuilt from the routes as they now stand) for the road-to-10 program's thin-doors lane:
the backend wiring map's finding that 31 of the edge's 51 routes and 16 of the dashboard's are "fat" (a door holding
rules or table queries itself). Scorecard categories Route Architecture (05), Separation of Concerns (04), Architecture
(01) and Complexity (27). One branch, no migration, no behaviour change. The lane builds and proves locally and does
not push; the controller folds it into wave 3's one pull request.

## 1. The rule, and the number that holds it

`baselines/route-doors.json`, written by the health lane, counts in `apps/edge/api/**` and
`apps/dashboard/app/api/**` each value import of `@chanlytics/db`, `@chanlytics/channels`, supabase-js, or the edge's
relative facade of the first two (`lib/packages/db`, `lib/packages/channels`). It stood at 54 imports in 50 route files
and may only fall. A door that imports none of them holds no repository read and no provider wire: everything behind
the knock is a call into `apps/edge/lib/<domain>/` (the edge), `apps/dashboard/src/server/<domain>/` (the dashboard) or
a core verb.

A door is: authenticate, parse (through `readBody` and the token helpers), call ONE verb, answer.

## 2. The moves

Each is a PURE MOVE: the body goes whole into the layer that owns it, its names and its logic unchanged, and the
door's own tests stay green unchanged. Proven three ways, all in the pull request: the door module's export list is
the same before and after (the moved module's is listed beside it); every line a door lost reappears verbatim in the
module that took it (`move-proof`, the unmatched remainder is the signature and the imports, and is read by eye); and
the door's existing tests (the signed deliveries of `whatsapp-door`, the cron doors' `_cron-doors-world`, the golden
probe) run unchanged. A bug found on the way is written down, never fixed inside the move.

1. **The cron doors** (`apps/edge/api/cron/*`, all one shape: logger, database, the sweep key, the sweep). One
   `sweepDoor` helper authenticates the sweep key, binds the logger and the database, and hands the sweep its tick; each
   sweep's body lives in its domain's folder (`lib/voice/calls-sweep.ts` and its kin) and each door is a few lines.
2. **The admin doors** (`apps/edge/api/admin/*`, `diag`, `retell-availability`, `jobs/tick`): `authorizeAdmin`,
   `readBody`, `workspaceFor`, one verb.
3. **The webhooks** (`retell-webhook`, `retell-fn`, `whatsapp`, `stripe-webhook`, `apify-webhook`, `inbound-sms`,
   `retell-inbound`, `resend-webhook`, `sms-status`): the wire is read and verified at the door through the domain's
   `verify…` verb, and the rest is the verb. A signed delivery's tests run the real POST.
4. **The dashboard's routes** (`apps/dashboard/app/api/v1/**`): the `read()`/`write()` declaration stays (it is the
   policy `route-policy.json` pins); its `handle` is one call into `src/server/<domain>/`.

## 3. What is not this lane's

The edge-lib and channels modules the map also calls fat are not doors: `email/sending-domains.ts`,
`reach-out/check.ts`, `lines-saga.ts`, `a2p-register.ts`, `waba-events.ts`, `outbound-gate.ts`, `receipts-watch.ts`,
`lead-sweep.ts`, `voice/forwarding.ts` and `a2p/steps.ts` stay as they are and are the next lane's. Functions over
150 lines that Wave E holds (retell-fn's POST, lead-db, sendBroadcastBatch) are moved whole and not split.

## 4. What the ratchets do with a move

Every per-file baseline is keyed by the file, so a body that moves is a key gone and a key new with the same numbers.
`UPDATE_BASELINES=raise` writes the new keys; the pull request states, per baseline, the total before and after, and that
no number rose. Falls are banked with `UPDATE_BASELINES=1`. The route-doors number is the one this lane exists to lower.
