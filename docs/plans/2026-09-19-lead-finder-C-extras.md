## Order, and what each one takes from B

- **1 and 2 first**, in either order: each is one door, one schema and one chip row, and each is what the first cohort will ask for ("it keeps finding chains", "show me the ones I can email"). 3 needs 2. 4 needs 3's reading of leads. 5, 6 and 7 are the catalog's growth and wait for a real ask that the one card cannot serve.
- Every item keeps B's rules: one keyboard listener, hookless components with their state on the page, the surface keyed by view, Undo as a server record, the owner's permission `find` for anything that counts, no vendor named, no dollar meter, every sentence from contracts, every test running code and never reading it.
- Every item that spends (2, 3's draft, 5, 6) says which budget it spends and how it is capped, the way B's Task 4.3 does for drafts; 6 spends the platform's, never a workspace's.
- The migration each needs takes the next free number at build time and is pushed by the agent, dry run first, as B's Task 22 says.

## What is measured before the first item starts

From G5's cohort, off the ledger: time to the first useful result; kept-lead precision (Keep and Put back against Not a fit); contact-ownership accuracy (drafts that bounced, calls that were wrong numbers); duplicate charges (a lead counted twice); cost per kept lead; customer-message latency on the shared jobs queue while a search runs. The item whose absence the numbers name goes first; an item nobody's use points at stays here.
