## What changes

1. **Lanes and fairness in `claim_due_jobs`: #1340's, not this branch's.** Another session built decision 0018 steps 2
   and 3 (`jobs.lane`, the claim's order and each workspace's turn at bulk work) while this lane was being written, and
   this lane builds on it. Its migration is numbered 00286 here, because 00267 sits below the ledger's head; the fold
   gives the final number. This branch adds what the lanes leave open:
   - **Jobs side by side** (0018 step 4, `CLAIM_SLOTS = 3`): a tick runs a few jobs at once, each claimed only when a slot
     is free to start it, so "claimed" still means "started". The lease (90 s) and the ceiling (60 s) are each job's.
   - **The measure's alarm**: a reply claimed more than a minute late pages the platform once a window. The heartbeat
     reads the lane from the claimed row (`jobs.lane`); TypeScript never decides a lane.
2. **Retry and dead letters.**
   - Jittered waits for every kind that retries (the ledger's `RETRY_WAITS_MS`, the send door's fresh-job waits, the
     broadcast throttle's back-off, the provider call's back-off): contracts' `jittered`, up to a fifth longer, never
     shorter, so every wait still outlasts the lease.
   - An unknown kind is kept, its claim given back, not failed: either deploy order works. It fails as never run after a
     day.
   - A back-office requeue door for a `failed` job (platform scope, `platform.acted` written first, as the lines' doors
     write it).
   - A `statement_timeout` for `service_role` (00281) and a fetch timeout in `createServiceClient`.
3. **A broadcast that cannot reach Graph (E:0):** a send that provably never left (a connection that never opened) gives
   the person back and the run waits as it does for a throttle; the finish alert says N of M reached and never "sent"
   when none left; a run that cannot reach WhatsApp pages once. **A stalled broadcast (E:1):** its minute-by-minute waits
   are counted and capped at thirty, then it fails with the owner told; a run that waited looks at the day's sending
   hours again before it sends. The reviewer's probe is a test.
4. **A push batch that timed out (defect 50):** `expoPush` tells `unknown` from `retryable`, and a batch whose outcome is
   unknown is said in the receipts, never thrown, so `push_send` does not tell the phones twice.
5. **Inbound work per conversation (category 15, 00282):** two near-simultaneous customer messages in one thread are
   answered once. The message about to be answered claims its thread's reply turn before the model is asked and asks
   again before the words go out; the newest holds it, and the drafts an older turn left waiting are withdrawn.
6. **A broadcast assembled in one transaction (category 15, 00280):** run, recipients and job in one SQL door
   (`assemble_broadcast`), so a function that dies between them leaves no broadcast without a job. The door asks what the
   insert policies ask, and 00270's template and playbook checks too.

## How each is proven

- The claim's order is #1340's `jobs-lanes.db.test.mjs`. The runner's slots, the deferral, the alarm and the lane read are
  `jobs-tick.test.mjs` and `jobs-tick-door.test.mjs`. "Claimed = started" and "a job that reaches a person never re-runs
  after an unknown outcome" keep their tests green.
- Each defect ships with a test that fails on `main` and passes here: E:0 (`broadcast-never-left.test.mjs`, the real
  channels send through the real door, and `core-broadcast.test.mjs`), E:1 (`core-broadcast.test.mjs`), defect 50
  (`expo-push.test.mjs`), the service role's bound (`service-client-bound.test.mjs`, and `privileges.db.test.mjs` for the
  role's setting).
- The database's part is proved on a stack: `assemble-broadcast.db.test.mjs`, `reply-turn.db.test.mjs`,
  `jobs-requeue.db.test.mjs`.

## Not built, and why

- **Event replay** (category 31, optional in the first plan): a script that replays one kind's events into a rollup. Left
  open; nothing in this lane needed it.
- **A decisions row for the requeue.** The first plan said "a `decisions` row and `platform.acted`". A decision is the
  workspace's own verb; the back office's doors record `platform.acted` (`platformLineAct`), and the requeue follows
  them.

payloads (observe lane); typed lint (road to ten wave 2); splitting `sendBroadcastBatch` (wave E).
