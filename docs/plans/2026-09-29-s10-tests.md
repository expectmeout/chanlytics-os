## What changed

1. **The fake database learns the schema.** `tooling/scripts/tests/_fake-db.mjs` reads a schema generated from
   `packages/db/src/database.types.ts` (each table's columns, which are NOT NULL with no default on insert, the foreign
   keys an embed follows, each function's arguments), the CHECK sets in
   `packages/contracts/src/schema-sets.generated.ts` and the unique keys the replayed migrations build
   (`tooling/scripts/tests/_unique-keys.generated.json`, written by `gen/unique-keys.mjs`, which `corepack pnpm
gen:db-types` runs), through `_schema.mjs`. It refuses what PostgREST and Postgres refuse, with their codes and
   words: an unknown table, column, function or embed (`PGRST205`, `42703`, `PGRST204`, `PGRST202`, `PGRST200`), a NOT
   NULL left empty (`23502`), a value outside a CHECK's set (`23514`), a second row on a unique key, primary or partial
   (`23505`), an upsert whose conflict target no key matches (`42P10`), a request line past the gateway's 8 KiB (about
   208 uuids in one `.in()`), and a read past `max_rows`. A bulk insert's missing key is NULL, an undefined value is
   not sent, a write with no `.select()` answers no rows. A unique key is judged when the write moves a column the key
   or its predicate reads, as Postgres does: a fixture that seeds five live lines in one workspace is not made a
   refusal by touching one line's `state_since`. A partial key's predicate sees the default of a column a row leaves
   out (`jobs.state` is 'scheduled': two `email_ingest` jobs sent with no state are one), `<>` and `NOT` leave out a
   row whose cell is NULL, and an update's values are judged against the rows it matches (one that matches none is
   refused none).
   **The double and the database are held to one answer.** `database/fake-db-agrees.db.test.mjs` sends twenty-four
   requests, and a read past `max_rows`, to the replayed stack and to the double, and they must agree on the code and
   the words; the request line's size is found by bisection on both. It found one difference on its first run (the
   words of a function called with no arguments), and the cases for defaults, NULL cells and a zero-row update were
   added with the reviewer's findings and agreed at once. `database/unique-keys.db.test.mjs` holds the generated keys to the
   replayed migrations, with none left unmodelled, and `database/fake-db-schema.test.mjs` holds each refusal and the
   translation of an index's printed definition.
   **Every fixture the stricter double caught was fixed at its root** (below).
   **Triggers:** each state machine that matters has one `*.db.test.mjs` that runs its writers' whole update sequence
   against the replayed Postgres (#1100's lesson: a writer's moves replayed by hand prove nothing): a broadcast through
   both guards (`broadcasts_guard` and `broadcast_recipients`, jobs' `sendBroadcastBatch` over the real service
   client), an escalation opened, taken over, handed back and resolved once, a job claimed, run and settled
   (`jobs_guard`, jobs' real `runTick`), a message from queued to read (`messages_guard`), a line's voice states
   (`lines_voice_guard`), and the lead finder's money lock (reserve, spend, settle, give back).
2. **`DB_PATHS` covers what the stack suites load.** `tooling/scripts/checks/db-paths-changed.mjs` names
   `packages/{core,jobs,db}`, `apps/edge/{api,lib}`, `apps/dashboard/src/{server,lib}`, `apps/dashboard/app/api`, the
   tests' shared helpers, the generators and the ledger the suites load, and `replay-range.mjs`. A test
   (`database/db-paths-changed.test.mjs`) follows every stack suite's imports on the syntax tree and
   fails one that loads a module outside the list; contracts and channels are named as not the database, reaching a
   suite only through a dist that is on the list (any contracts change rewrites core's, jobs' and db's dists, which bundle it). Measured on main's 84 commits since 28 September: the old gate
   replayed on 30 and skipped 9 that changed a module a suite loads; this one replays on 53 and skips none of them.
3. **One clock.** `pnpm test` and `pnpm test:db` run through `tooling/scripts/checks/test.mjs`, which sets `TZ` before
   Node starts: UTC, or `TEST_TZ`'s zone (`shared/the-suite-runs-in-one-zone.test.mjs` runs it and reads the zone a
   child sees). The 29 tests in 11 files that failed under `Pacific/Auckland` on 29 September, and how each was
   fixed, are in the pull request. A test that named an instant with no zone now carries the offset it means
   (`broadcasts`), one that read the wall clock pins `Date` with `t.mock.timers` (`calendar-feed`, `reply-read-door`,
   `reach-out-routes`, `cron-reach-out-door`'s reconcile), and Ask's quick answer, which read "tomorrow" in the
   machine's zone when a workspace had none, reads it in UTC, the edge's zone
   (`shared/a-day-with-no-zone-is-utc.test.mjs`, run twelve hours east). The words that say a Stripe instant's day in
   the viewer's zone (the billing pane and Setup, a sending domain's hold, a partner's "since") are left as they were:
   they are the viewer's day on purpose, and the four tests that assert them pin the viewer they describe
   (`fixtures/pin-utc.mjs`, imported before contracts loads). The calendar's day labels are the defects lane's (fix 9,
   UTC day keys). CI's "Node suite, Pacific/Auckland" leg, added by the ci lane as non-failing, fails the run now:
   `continue-on-error` and its note are gone from `ci.yml`, the workflow's one change here.
4. **Coverage.** A full run in UTC has Node measure line coverage (`--experimental-test-coverage`, the lcov reporter,
   and `checks/tap-reporter.mjs` so the runner's file-by-file table stays out of the TAP) and prints it per package
   and tree; three areas are held at a floor in `baselines/coverage.json`: core, the edge's doors and the dashboard's
   routes. A package runs from its committed dist, one bundle, so its lines are read back to the module that wrote
   them by the bundler's markers (inlined data and another package's code do not count); a tree is its tracked files,
   one no test loaded counting in full. A floor sits a point under the measure and only rises (`UPDATE_BASELINES=1`);
   lowering one is `COVERAGE_FLOORS=lower`, argued in the register. `checks/coverage-floors.test.mjs` holds the
   reading, the verdict, the bank and the reporter, and runs Node's own runner once for real. Measured 29 September
   2026: core 100.0%, jobs 97.9%, db 75.2%, channels 63.6%, contracts 88.1%, the edge's doors 97.8%, its lib 97.6%, the
   dashboard's routes 94.8%, its server 95.7%.
5. **The nightly's node failures.** `workspace/control-plane.integration.test.mjs` allows the partner role (I1:0: it
   reads contracts' `MEMBERSHIP_ROLES`, held to the CHECK at compile time, instead of a copy written before 00201); the
   two reach-out cron door tests clear `SUPABASE_URL` and the service key for their no-database step (I1:1, the ci
   lane's #1344 did it, and its `withEnv` is the one kept); the source-scan ratchet counts the calls of a test's own
   helper that reads a source file (`sourceReads` in `_ast.mjs`), raised as a correction of the measure.
6. **Row factories.** `tooling/scripts/tests/_rows.mjs`: a factory per table for the ten the fixtures write most
   (tenants, tenant_config, contacts, conversations, messages, events, tenant_channels, lines, memberships,
   billing_accounts), each filling every column the table has, typed from the schema at the moment a row is made: a
   key the table does not have, a NOT NULL column the factory names no value for, and a value the database would refuse
   are each refused by name (`database/row-factories.test.mjs`). The shell's page tests keep the stub React.
7. **Smoke.** `tooling/scripts/checks/smoke.mjs` asks the edge's `/api/health` and the dashboard's `/api/version`
   after a deploy and judges the answers (`checks/smoke.test.mjs`, against a local host that answers well and badly);
   `tooling/scripts/ops/golden-edge.mjs --no-secret` runs the probes that need no secret against a preview's
   `VERCEL_URL` (`ops/golden-edge-no-secret.test.mjs`). `docs/runbook.md`, Deploy, has the command. No workflow runs
   them: the ci lane's `preview-smoke.yml` runs the credential-free browser specs instead.

## Fixtures the stricter double caught

Each was a fixture that lied about the table, none a defect in the code under test, and each was fixed in the fixture:
the strict double's first run over the whole suite found the unique-key cases below; the rest the earlier columns,
NOT NULL and CHECK refusals had found before this branch was resumed (`ask/ask-routes.test.mjs`'s jsonb tests wrote a
made-up table `t`; they write `ask_messages` now).

- Five live lines in one workspace, seeded by `cron/cron-doors-b.test.mjs`, `cron/cron-playbooks-door.test.mjs` and
  `lines/line-recovery.test.mjs`, a state the database cannot hold: the sweep's update of one line's `state_since` was
  refused. The fix is in the double, not the fixtures: a write is judged against the keys it reaches, as Postgres does,
  and these files are untouched.
- `email/resend-webhook-door` counted two jobs for one email received twice (once signed by each Resend account): the
  ledger's key is the mailbox and the received id, so the database makes it one, and the double does since it read a
  partial key's default. The test posts two emails and asserts that the same one again is the job it already was.
- `database/fake-db-schema.test.mjs`'s own cases: a `lines` insert with no `provider`, and a workspace-wide update that
  made two contacts share an email.
- The lead finder's money-lock walk reserved $0.30 for a search, under the actor's $0.50 cap floor, so no run started:
  it reserves $0.60.

## Other suites fixed on the way

- **Two races between database suites**, found by running the whole suite on a clean stack: `lead-lists.db` and the
  money-lock walk both read, add to and rewrite the platform's `lead_platform.tenants_on`, so a write was lost and a
  workspace found its searches paused (5 failures in one run); and the job walk, the broadcast walk and
  `jobs-outbox.db` make jobs due in, and count, the one ledger (`jobs_backlog()` failed once in three runs with the
  walks beside it). Each group takes a file lock for the whole file (`_file-lock.mjs`, held by
  `shared/a-file-lock-serialises-two-holders.test.mjs`), and the eight suites ran together four times, green each time.
- **The partner letter tests** (`partner.db`, `handover.db`, `partner-invite.db`) compared the runner's `new Date()` with
  timestamps the database wrote at `now()`, and failed whenever the two clocks differed by a few milliseconds; they ask
  `partner_letters_due` with no instant, its own default `now()`.
- `never-again.db` and `reply-away.db` compared a migration's text with `pg_proc`'s body whole, and failed on a
  Windows checkout (CRLF); both sides are read with LF endings.
