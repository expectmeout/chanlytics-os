## What changes

1. **The fake database learns the schema.** `tooling/scripts/tests/_fake-db.mjs` reads a schema generated from
   `packages/db/src/database.types.ts` (each table's columns, which are NOT NULL with no default on insert), the CHECK
   sets in `packages/contracts/src/schema-sets.generated.ts`, and the unique indexes the migrations create. It refuses
   what PostgREST refuses, with PostgREST's code and message: an unknown column in an insert, update or select list
   (`PGRST204`/`42703`), a NOT NULL column left empty (`23502`), a value outside a CHECK set (`23514`), a duplicate
   primary key or unique key (`23505`), an `.in()` past the URL's length (about 208 uuids: a `414`/`URI too long` the
   client reports as an error), and it answers at most `max_rows` (1,000) rows a read. A table the schema does not
   know is refused by name, so a fixture cannot invent one. Every fixture or writer the stricter double catches is
   fixed at its root and listed in the pull request as a real defect or a fixture that lied.
   **Triggers:** each state machine that matters gets one `*.db.test.mjs` that runs its writers' whole update
   sequence against the replayed Postgres (#1100's lesson: a writer's moves replayed by hand prove nothing):
   `jobs_guard` (the tick's claim, run, settle), `messages_guard` (the send door's queued, sent, delivered, failed),
   `broadcasts_guard` with `broadcast_recipients` (jobs' `sendBroadcastBatch` and the settle, over the real service
   client), `escalations_guard` (open, accept, resolve), `lines_voice_guard` (the line's voice states) and the money
   lock (the lead reserve and settle).
2. **`DB_PATHS` covers what the stack suites load.** `tooling/scripts/checks/db-paths-changed.mjs` adds
   `packages/{core,jobs,db}/src/**`, `apps/edge/{api,lib}/**`, `apps/dashboard/src/server/**` and
   `apps/dashboard/app/api/**`. A test follows every stack suite's imports, transitively, and fails when one loads a
   module outside the list, so the list cannot fall behind again. Measured: how many of the 84 main commits since 28
   Sep would now run the replay (11 were skipped that should not have been).
3. **Determinism.** `pnpm test` and `pnpm test:db` run through a small node launcher that sets `TZ` before node
   starts (`TZ=UTC` unless `TEST_TZ` names another zone), cross-platform with no new dependency; `TEST_TZ=Pacific/Auckland
corepack pnpm test -- <globs>` runs the time tests in another zone. The 18 tests that fail under Auckland are fixed
   at the root: the tests' own clocks here (a date built with no zone, a day read in the machine's zone); the
   calendar's day labels are the defects lane's (`calendar-words.ts`, their item 9), and until it lands those tests
   pin the zone they assert in. Every test that reads the real clock pins it with `t.mock.timers` (the reach-out
   block test's midnight edge, the cron door reconcile), starting from what #1328 already pinned (the broadcasts "not
   now" and the reach-out approval clock are left alone).
4. **Coverage.** `--experimental-test-coverage` over the suite, reported per package in the suite's output; floors for
   three areas (core, the edge's doors, the dashboard's routes) held by a test that reads the report, so a number may
   only fall with a reason. The measured numbers are a row in `docs/debt.md`.
5. **The nightly's node failures.** `workspace/control-plane.integration.test.mjs` allows the partner role (I1:0);
   the two reach-out cron door tests clear `SUPABASE_URL` and the service key as the other five do (I1:1); the
   source-scan ratchet counts the reads made through local helpers (`read(...)`, `src(...)` over `readFileSync`) in
   the four files named on 28 Sep, raised as a measure correction.
6. **Row factories.** `tooling/scripts/tests/_rows.mjs`: a factory per table for the ten tables the fixtures write
   most, each filling the NOT NULL columns with made-up values typed from the schema, so a fixture names only what its
   test is about. It replaces hand-typed rows where a test broke under item 1. The shell's page tests keep the stub
   React (real React and a DOM is the shell lane's call).
7. **Contract and smoke.** `tooling/scripts/checks/smoke.mjs <base-url>` hits `/api/health` and `/api/version` and
   fails on anything but a 200 with the expected shape. The golden-edge probes that need no secret run against a
   pull request's preview when `VERCEL_URL` is present (the workflow step is below, for the ci lane).

## For the ci lane (`.github` is theirs)

- `ci.yml` and `database.yml` need nothing new for items 1 to 6: `pnpm test` and `pnpm test:db` set their own zone.
- A job (or a step after Vercel's preview deploy) that runs `node tooling/scripts/checks/smoke.mjs "https://$VERCEL_URL"`
  and the secret-free golden-edge probes, `node tooling/scripts/ops/golden-edge.mjs --base "https://$VERCEL_URL"
  --no-secret`, when the deployment status event names a preview.
- Optional: a `TEST_TZ=Pacific/Auckland` leg over the time files (the list the launcher prints with `--time-files`).

## For the defects lane

`calendar-words.ts`'s day labels in the workspace's zone are theirs. The tests that fail under Auckland because of it
are named in the pull request; this lane fixes the tests' clocks and leaves the words.

## For the health lane

The `.rpc(` ratchet is theirs. The fake's refusals change no `.rpc(` call.

## How each is proven

- The fake's refusals: `database/fake-db-schema.test.mjs`, a refusal per class, with PostgREST's code, and the stack
  suite `database/fake-db-agrees.db.test.mjs` that sends the same bad writes to the replayed stack and reads the same
  codes back, so the double and the database are held to one answer.
- `DB_PATHS`: `database/db-paths-changed.test.mjs` walks each stack suite's imports and fails a module outside the
  list; the 84-commit measure is in the pull request.
- The zone: `repo/test-launcher.test.mjs` runs the launcher and reads the zone a child sees; the 18 tests pass under
  `TEST_TZ=Pacific/Auckland`, `UTC` and `America/New_York`.
- Coverage: `repo/coverage-floors.test.mjs` reads the report the launcher writes and fails an area under its floor.
- The nightly's node tests: run with `SUPABASE_URL` set (and against a stack with a partner membership).
