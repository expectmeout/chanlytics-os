## 1. The dashboard reads its environment once

Today the dashboard reads `process.env` 49 times in 23 files, and neither app checks its environment at boot.

- `apps/dashboard/src/server/env.ts`: one zod schema over every server variable, read once, each value trimmed and
  blank as unset, with typed getters named for what they give (`edgeUrl()`, `supabaseServiceKey()`, …). A variable a
  production deployment cannot serve without is `required` in production (`VERCEL_ENV === "production"`), and a
  missing one is named by `productionProblems()`.
- `apps/dashboard/src/lib/public-env.ts`: the browser's `NEXT_PUBLIC_*` values, each read by its literal name so
  Next inlines it at build, and nothing else. Browser code imports only this one.
- A lint rule (`no-restricted-properties` on `process.env`, as the edge's) makes a read anywhere else under
  `apps/dashboard` (server, app, the root's `proxy.ts`, `next.config.ts`, `instrumentation.ts`) an error.
- `env-manifest.test.mjs` holds `env.ts` plus `public-env.ts` and `apps/dashboard/.env.example` to one list, as it
  does the edge's.
- The production URLs written as code defaults (the edge's URL in `src/server/edge.ts`, the dashboard's origin in
  `dashboard-origin.ts`, the lead wires' base in `lead-wires.ts`, the public origin in `origin.ts`, the voice shell's
  origin in `voice-shell.ts`) become required in production: a preview or a laptop keeps a default where one is
  harmless, and production refuses to boot without its value.
- Both apps validate at boot in `instrumentation.ts` (`register()`): the dashboard through `env.ts`, the edge through
  its own `env.ts` (a `productionProblems()` there). A production boot missing a required variable logs one line,
  `env_invalid` with the names (never the values), and throws, so the deployment fails its first request loudly rather
  than on the first use of a missing secret. Tests run `register()` over a production environment with a hole.

## 2. Security switches fail closed, with sunsets

Four rollout fallbacks default to the weaker mode, and their retirement dates live only in `docs/debt.md`'s prose.

- A registry, `packages/contracts/src/shared/security-switches.ts` (or the edge's `lib/` if it needs no sharing): one
  row per switch with its name, the weaker mode it allows, the date it must be gone, and the log event that proves the
  world is ready (`voice_door_auth` with `sig: true`, `admin_door_key_only`, …).
- The four: `RETELL_DOORS_SIGNED` unset (voice doors take the shared secret), `DIAG_KEY` opening every admin door on
  an edge without `EDGE_CALL_SECRET`, `GOOGLE_OAUTH_STATE_SECRET` falling back to `DIAG_KEY`, `RETELL_WEBHOOK_KEY`
  falling back to the API key.
- `repo/security-switches.test.mjs` fails once a row's date has passed while its code still reads the fallback, so
  the sunset is a red build, not a sentence. The dates are `docs/debt.md`'s (3 October 2026 read, retirement after a
  clean week).
- Fail closed where it needs no production log read: in production the dashboard refuses to sign an OAuth state with
  `DIAG_KEY` when `GOOGLE_OAUTH_STATE_SECRET` is unset (boot validation names it). The two switches that need the
  3 October read (`RETELL_DOORS_SIGNED=1`, the preview's `EDGE_CALL_SECRET`) are listed under Ruben's switches, not
  flipped.

## 3. Edge tokens: a nonce that is checked, a body that is bound, a workspace on every door

`packages/channels/src/tokens/edge-token.ts` mints a nonce that nothing checks and binds no body.

- The edge keeps a small nonce cache (per instance, bounded, entries expire with the token's minute) and refuses a
  token seen before: `replayed`. A token that carries a body hash (`bh`) is checked against the request's raw body for
  POST doors; the dashboard's `callEdge` mints it. An older dashboard's token without `bh` is still accepted until a
  sunset row in section 2 says otherwise, so either deploy order works.
- The five door tokens that name no workspace or person (whisper, stop-call, hand-over, steer, and the one the census
  finds; `src/server/conversations/live-call.ts`, `thread-control.ts`; defect 25) name both, and the edge checks that
  the call or the draft belongs to the token's workspace before acting. Tests over the door world: a replay, a changed
  body, another workspace's call id, each refused.

## 4. A fresh session before the sensitive acts

`getClaims()` verifies the JWT locally, so a revoked session passes until it expires.

- A route may declare `fresh: true` in its policy; `withRoute` then asks `getUser()` (the auth server) before the
  handler runs, and a session the server no longer knows is refused 401. Erase (a person, a lead), export, a role
  change, billing and account deletion declare it; `route-policy.json` pins each declaration through the existing test.
- The session cookies: `secure` in production and `sameSite: lax` where `@supabase/ssr` lets us set them; `httpOnly`
  is not possible while the browser client reads the session from the cookie (the shell's realtime and Ask use it),
  which the plan records rather than breaks.

## 5. The database: INSERT fences and tenant-true parents

- 00273: `grant insert (columns…)` on each session-writable table, like 00121's UPDATE fences, so a session cannot
  write a column the edge owns; a `insert_fence` rule in `privileges.db.test.mjs` fails a session-insertable table with
  a whole-table INSERT grant.
- 00274: composite `(tenant_id, id)` foreign keys where a child's parent must share its tenant (conversations,
  calls, escalations, notes, deals and the rest the census finds), `messages` left to the defects lane's 00266.
  A tenancy db test inserts a child pointing at another tenant's parent and is refused.

## 6. SSRF: resolve, then refuse

`feedUrlOk` checks the hostname string, so a public name that resolves to a private address passes. Every server-side
fetch of a user-supplied URL (the calendar feed, the business website read, lead pages) goes through one guarded fetch:
https only, the name resolved and every address refused if private, loopback, link-local, CGNAT or metadata, at
connect time (a `lookup` on the agent, so a rebinding between check and connect cannot pass), and each redirect hop
checked again. Tested with a fake resolver.

## 7. `tenantDb(tenantId)` on the edge

A service-role client whose `.from()` must be followed by `.eq("tenant_id", …)` before it executes, or opened with
`platformWide()` for the sweeps that are platform-wide by design. The doors' statements move onto it; the rest of the
edge's 63 tenantless statements are listed here as they are counted, and moved where the organization wave's files
allow.

## 8. CSP nonces

script, keeping `e2e/csp.spec.ts` meaningful. If it cannot be proved without the browser, this section becomes the
plan and stops there.
