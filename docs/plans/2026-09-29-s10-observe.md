**As built (29 September, the lane's one branch).** Every section is done; where the build differs from what is
written below, it says so here and nowhere else:

- Events carry the request's name as a column, `events.request_id` (00279: the TypeScript writer stamps it, and the
  column's default reads it from the header the database client sends on every call, so a SQL function's rows say it
  too), not inside `data`.
- The name is also signed into the edge token (`rid`), and an admin door is named by what a verified token signed; a
  header names only a call with no verified token, for its own lines.
- A line carries no `ts`: the platform (and any drain) stamps it as it arrives.
- The redaction goes further than section 3's keys: credentials by name and by shape, and a contact or credential
  quoted inside any string (`channels/src/log/redact.ts`).
- The beacon's route is on the account (the sign-in pages have no workspace) and takes an optional workspace, which
  the route's own resolver accepts only for a member of it.
- Section 6 declares one shape and one version for the three kinds in contracts (`workspace/event-data.ts`,
  `SHARED_EVENT_SHAPES`, `SHARED_EVENT_VERSIONS`); the SQL writers keep the column's default version, and the database
  suite runs each of them and fails the day a declared version rises without them.
- Ask's modules are on the logger too: the lint exclusion is gone.
- A recording's playback is the decision `open_recording` (one per member per call per hour), not `recording.played`,
  and the shapes of section 6 are one loose object per kind (every writer's field optional, extra fields allowed)
  rather than a union told apart by `source`: a SQL writer's evidence rides along, and the database suite holds each
  writer's row to it.
- A browser's error is logged as a warning (`client_error`), so a drain's alert on `level = error` stays about the
  platform.

Peer lanes own neighbouring files: the jobs lane owns the ledger (this lane touches `schedule()`'s

## 1. One logger, as a package module (A:1)

- `packages/channels/src/log/`: the one implementation. JSON per line, `level`, `event`, `ts`,
  `request_id` from one `AsyncLocalStorage`, an Error as `{ message, stack }` under `<key>_error`,
  redaction by key inside the logger (section 3). `requestIdOf` already lives in channels.
- `apps/edge/lib/log.ts` and `apps/dashboard/src/server/log.ts` re-export it. The edge keeps its closed
  `LOG_EVENTS`; the dashboard's names become a second closed set held the same way, and the test
  holds both ways.
- `packages/core` and `packages/jobs` log through it (they may import channels). `packages/db` may not:
  it takes a logger port (`setDbLogger`) whose default writes the same JSON shape, and the edge and
  the dashboard install the package logger at boot.
- Lint: `no-console` covers `packages/*/src/**` and the dashboard's `app/auth/**`; the exceptions are
  Ask's modules, listed with the program that owns them.
- One tenant field: `tenant_id` everywhere; a test over every logger call's keys holds it.

## 2. The request id end to end

- Minted in `withRoute` (done in #1332).
- `schedule()` stamps `request_id` from the async context into the job payload; the tick binds the
  job's `request_id` (or the job id when none) while the job runs.
- Every edge door binds one: a webhook's delivery, a cron, the tick; each edge answer carries
  `x-request-id`.
- Events carry it in their data (`request_id`), stamped by the one writer from the context.
- The edge's `bindRequestId` (`enterWith`) is proven not to leak across two requests in one instance,
  or it moves to `als.run`.

## 3. Redaction inside the logger

Keys `phone`, `to`, `from`, `email`, `body`, `text` (and their `_`-suffixed forms) are redacted in every
call: a number keeps its last two digits, an email its domain, a body its length. A planted-value test
runs a door and greps its stdout for a fixture number and body. The two known leaks are fixed:
`admin/google.ts` (the owner's email) and `retell-fn.ts` (a raw provider error body).

## 4. A client error beacon

`ShellErrorBoundary` gains `componentDidCatch`; it, `app/(os)/error.tsx` and the auth pages post to
`POST /api/v1/client-errors` (a `route()` with a rate bucket and a contracts body schema carrying no
PII), logged as `client_error` through the one logger with the request id. A test runs it through
`withRoute`.

## 5. The breaker opens in silence (F:1)

`breaker_open` and `breaker_closed` are logged with the provider; `/api/diag` reports each provider's
breaker state from `breakerOf`.

## 6. One shape per event kind (A:0)

`contact.added`, `contact.consent_changed` and `platform.acted`: the declared shapes in
`packages/db/src/events.ts` widen to the shapes SQL writes (a union by `source`), each SQL writer
states the version it writes, and a test reads both writers' shapes. A migration only if a SQL
function must change (00279).

## 7. Recording playback is audited

Playing a recording writes a typed `decisions` row (`recording.played`), and the team audit write that
is non-fatal today joins its state change's transaction.

## 8. Platform metrics rollup

A daily `platform_metrics` row per workspace (messages in and out by channel, replies answered, held
and handed off, p95 brain latency, provider failures by outcome, tokens) from a SQL rollup function on
a registered clock (00279), a back-office read, and an alarm when a workspace's answer rate is zero for
a day. Field p75 (#1328) is not duplicated.
