# The takeover checklist

Could a senior developer take this repository over tomorrow? This page scores
the codebase against the properties that make that possible, says where each
one stands, and lists what to do next.

It was first scored by hand on 21 September 2026 at `f68aeef`, and by the 26th
the nine-reviewer scorecard found it stale in fifteen places. It was re-scored
on 27 September at `519724e9c`, after the organization program merged (#1161),
from the debt register (`docs/debt.md`) and the code. The numbers the build
holds are no longer typed here: the block below is the register's, rewritten by
`UPDATE_BASELINES=1 corepack pnpm test`, and `debt-register.test.mjs` fails when
it differs from the baselines. Every other count on this page was read at
`519724e9c`; re-derive it before quoting it.

Chanlytics OS is a backend-heavy, multi-tenant, provider-driven system with a
ported single-page shell on top, so the usual frontend-first checklist is
translated: where it asks about hooks and state libraries, this page asks
about the surface seam and the session stores the shell actually has.

**Strong** means a senior developer would nod. **Partial** means the pattern
exists but is not universal or not written down. **Gap** means it is missing.
The column _Since 21 September_ says whether a status moved, and whether #1161
moved it. Most of what #1161 did is to measure a number and hold it: that
stops a row falling, and a row rises only where the number itself went down or
the structure changed.

## The takeover test, answered

1. **Authentication**: `apps/dashboard/proxy.ts` (the gate and the pinned public list), `src/lib/supabase/server.ts`, `src/server/auth-cookies.ts`, `app/auth/*`.
2. **Authorization**: `src/server/route.ts` (`role` and `scope`), `ROLE_PERMS` in `packages/contracts/src/config/config.ts`, RLS in `supabase/migrations`, SECURITY DEFINER doors.
3. **Database client**: the session client in `src/lib/supabase`; the service role in `packages/db/src/service-client.ts` and the dashboard's `src/server/service-db.ts`; the edge's `apps/edge/lib/pg.ts`.
4. **API calls**: a page calls the bridge (`src/legacy-bridge/api.ts`), which calls the typed client (`src/client/api.ts` over `routes.generated.ts`), which calls `app/api/v1`. The dashboard reaches the edge through `src/server/edge.ts` with a per-call token.
5. **Business logic**: `packages/core` verbs; the receptionist's decisions in `apps/edge/lib`; privileged writes in SQL doors. Booking logic lives nowhere, by charter: the receptionist never books.
6. **Shared components**: `src/legacy/components` and `src/legacy/styles/tokens.css`.
7. **Feature components**: `src/legacy/pages/<surface>*.jsx`, fed through `src/legacy-bridge`.
8. **Global state**: `docs/architecture.md`, The shell; the `*_STORE`s and who owns them in `apps/dashboard/src/legacy/CLAUDE.md`; which surface retires each in decision 0015.
9. **Server state cache**: `surface-cache.ts`, `read-cache.ts`, `surface-runner.ts`, `surface-realtime.ts`, `refresh-map.ts`.
10. **Errors**: `AppError` in `packages/contracts/src/shared/errors.ts` and the envelope in `route.ts`, `refusalOf` in `packages/contracts/src/shell/refusal.ts`, `FailedRead` and `EmptyState` in `data-bits.jsx`; the edge's logger in `apps/edge/lib/log.ts` and the pager in `apps/edge/lib/ops/page-operator.ts`.
11. **Form validation**: the zod `input` on every route that declares one; field-level problems come from contracts. There is no form library, by design.
12. **Permissions**: `ROLE_PERMS`, `route()`, `roleGate` in the UI.
13. **Multi-tenancy**: `docs/architecture.md`, Tenancy; `docs/glossary.md` for the tenant and workspace rule.
14. **Integrations**: `packages/channels` adapters; doors under `apps/edge/api`; Stripe in `apps/edge/lib/billing/billing.ts`.
15. **Background jobs**: `packages/jobs`, `apps/edge/api/jobs/tick.ts`, the sweeps under `apps/edge/api/cron`.
16. **AI**: one receptionist (`apps/edge/lib/receptionist/brain.ts`, the composer in `packages/contracts/src/config/config.ts`, the structured answer in `contracts/config/brain.ts`); Ask under `src/server/ask`; the lead judge in `packages/channels/src/lead-judge.ts` and `core/leads`. The mockup's agent fleet is not built, by decision.
17. **Adding a feature**: `CLAUDE.md`, Where new code goes, and the canonical example table.
18. **Reusing a component**: `src/legacy/components`, and the `btn`, `set-input`, `record-*` classes the pages already use.
