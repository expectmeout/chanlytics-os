01The loop, verified

One decision anywhere must show up everywhere. This is the contract the whole app hangs on — here is the measured wiring.

  1. Button fires a store method — never a local mutation. 9 session stores (IX_STORE, FL_STORE, AS_STORE, LM_STORE, LD_STORE, INT_STORE, ST_STORE, SG_STORE, BC_HISTORY_SEED) own all cross-surface writes.
  2. Store dispatches a CustomEvent — 23 event types, all declared in CLAUDE.md, all dispatched from the store layer or the owning page.
  3. Surfaces re-render — inbox:decisions alone has 13 subscribers (dashboard, calendar, client profile, conversations, pipeline, reports, tasks, sidebar, topbar…). Fleet status changes reach 5 surfaces; store installs reach 3.
  4. Toast confirms with undo — one shared usePPToast; undo is a snapshot-restore that re-dispatches, so listeners roll back too.

Deliberate exceptions, all documented: broadcasts.jsx unshifts into BC_HISTORY_SEED and segments.jsx pushes into CLIENT_SEGMENTS — the two sanctioned cross-file writebacks in CLAUDE.md, each paired with an event (broadcasts:sent, segments:new).

02Plug-and-play seams

The mockup is structured so real data replaces seeds without touching page code. Three seams, in order of how they'd be wired.

SeamToday (mock)Backend swap
Read pathSeed objects on window.*, loaded by script order before any page parses. Pages read via (window.X || []).Replace each data/*.jsx with a fetch that populates the same globals with the same shapes, then mount. Page code unchanged.
Write path9 store objects; each method mutates memory + dispatches an event.Each store method body becomes an API call (IX_STORE.set → POST /decisions, FL_STORE.setPerm → PATCH /agents/:id/perms, AS_STORE.install → POST /fleet…). Method signatures and events stay; optimistic update is already the behavior.
Push pathCustomEvent on window; scripted arrivals (LD_STORE.arrive, handoffs) simulate server push.A websocket/SSE client re-dispatches the same 23 events. Every surface already subscribes — live updates come free.

The one structural requirement: ~30 pages destructure seeds at module scope (const { THREADS } = window.INBOX_DATA at top of file). Safe today because script order guarantees data-before-pages; with async fetch, the boot sequence must keep that guarantee — load data, then mount React (a single gate in Chanlytics.html). Moving all reads to render time is the alternative but touches every page for no user-visible gain. Recommendation: keep the boot-gate contract, document it in CLAUDE.md at swap time.

Session stores are intentionally non-persistent (reset on reload) — in production that persistence moves server-side through the same methods, so nothing is lost by design.
