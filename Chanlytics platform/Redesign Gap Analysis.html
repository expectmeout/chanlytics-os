Chanlytics · Internal

Redesign Gap Analysis

Legacy: Chanlytics/chanlytics @ main (Next.js 15, ~90 routes) Next-gen: this project (Chanlytics.html) July 13, 2026

The legacy app is feature-rich but structurally exhausted: ~90 dashboard routes, a 158 KB settings monolith, three competing table engines, duplicated sidebars and data-tables, and 40+ status docs riding along in the repo. The redesign is the opposite — a coherent agent-first OS with a smaller, sharper surface set. This doc maps every legacy surface to its place (or absence) in the new design, so "more complete" gets defined deliberately rather than by re-accreting everything.

01Two products, one direction

Legacy — feature accretion

nav: Dashboard · CRM · Conversations · Marketing · Agent Store · Agent Studio
  • Analytics dashboard as home; agents live in sub-pages
  • Airtable-class CRM tables (grid/board/calendar/gallery/form views, formula/lookup/rollup fields, sharing, undo)
  • Assistant + persistent chat threads in sidebar
  • Forms builder, Knowledge base, Reviews & Referrals, AI video creation, Social
  • Billing/credits, affiliate payouts, full internal admin console
  • User-customizable nav (rename, hide, reorder, custom groups)

Next-gen — agent-first OS

nav: Today · Inbox · Workspace · Intelligence · Settings
  • Today = operator's brief: approvals, needs-you queue, live agent state
  • Unified Conversations (Live, Calls, Chats, Email) + Live monitor
  • Agent Fleet as first-class management console; Store + Studio kept
  • Campaigns (Outbound, Content, Broadcasts), Pipeline with agent attribution
  • Ask everywhere (⌘K), active-agents rail, credits chip
  • Tasks, Reports with shared read-only links, focused 6-tab Settings

03Gap backlog, prioritized

P1

Parity blockers — users can't migrate without these

  • Assistant thread history. Chat is the product's spine; losing threads on close is a regression. Fold in: recent-chats list under the New Chat button (as legacy's NavChats), or a history drawer inside the Ask bar.
  • Leads + Segments. Both are nav stubs; legacy covers them via contacts + custom tables. Fold in: build People → Leads (qualify/approve queue) and Segments (agent-built smart lists) — this also absorbs 80% of what custom tables were used for.
  • Forms. Top-of-funnel capture that feeds Leads. Fold in: Campaigns → Forms, scoped down: field list + preview + submissions inbox. Skip legacy's full builder chrome at first.
  • Knowledge base. What agents ground on; adjacent to but distinct from AI memory. Fold in: Intelligence → Knowledge, sharing the memory provenance pattern from Settings → AI memory.
  • Team management. Invites, roles, seat management. Fold in: Settings → Workspace, second section. No new nav needed.
P2

Differentiators worth carrying forward

  • Reviews & Referrals. Revenue-adjacent and loved; Review Bot already exists in the Fleet. Fold in: Campaigns → Reviews, run as an agent playbook rather than a standalone tool.
  • Creative generation (AI videos). Keep the capability, lose the standalone page. Fold in: "Generate" action inside Campaigns → Content; the composer becomes an agent task with review in Inbox.
  • Notifications center. One place for everything that pinged you, with push. Fold in: bell → popover feed; full history lives as an Inbox filter, not a new page.
  • Agent observability. Memory health, MCP tool status, error streaks. Fold in: Fleet → agent detail → Health tab; ambient integration-health dot moves to the topbar.
  • Custom table views (scoped). If Segments proves insufficient, add saved views: grid + board only, filter/sort/group. Explicitly not: formula/lookup/rollup fields, gallery/form views, view sharing — that's how legacy got overworked.
P3

Ops & deliberate exclusions

  • Admin console (credits, disputes, payouts, pricing, phone-number requests) — rebuild as a separate internal tool; keeps the product shell clean.
  • Affiliate program — carry only if the growth channel is active; lives in Settings → Billing if so.
  • Onboarding tour — design once the P1 surfaces land; Today's brief is the natural guide.
  • Drop for good: property valuation (→ Store agent), nav editor, base/ + origin-table experiments, duplicate data-tables (call-data-table + -v2, client-management-table + -v2), sidebar copies, page2.tsx.

04What the legacy app teaches us not to repeat

  • One engine per pattern. Legacy has three grid/table engines (crm/[slug], views/all-tasks, origin-table) and two kanbans. The redesign should have exactly one list, one board, one profile pattern — reused everywhere.
  • No monoliths. A 158 KB SettingsClient and 55 KB create page are why "overworked" reads as slow. Keep the redesign's page-per-file discipline.
  • Configurability is not IA. Legacy let users rename/reorder nav because the default IA wasn't trusted. Ship the opinionated nav; measure before re-adding knobs.
  • Agents are the product. Legacy bolts agents onto a CRM; the redesign's Today/Fleet/Autonomy framing is the actual thesis. Every carried-over feature should be re-expressed as something an agent does with your approval — not another manual tool.

Bottom line: the redesign already covers or upgrades ~70% of legacy's user-facing surface with a third of the IA. Five P1 gaps (chat history, leads/segments, forms, knowledge, team management) stand between this design and true migration-readiness; everything else is either a scoped fold-in or a deliberate kill.
