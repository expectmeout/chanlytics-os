Chanlytics · Completeness audit

What's left to finish the frontend

Scope: the whole live app — surfaces, scenarios, and fine-grain nuance Method: traced against the code, not the screenshots Reads as: Built · Partial · Missing, prioritized P1–P3

The core is done and the agent-platform loop is unusually deep. What remains splits three ways: five surfaces that legacy had and users will miss, a band of scenarios the happy paths don't yet cover (partial failures, empty results, "something changed while you were looking"), and a layer of nuance — focus handling, pluralization, mobile density — that separates "demos well" from "ships." None of it is architectural; the stores and patterns to hang it on already exist.

00Already solid — don't re-open these

An honest audit starts by crediting what's load-bearing and finished, so effort goes to real gaps.

  • Built Resilience frame — ShellErrorBoundary catches a broken pane without taking down the OS; unknown routes land on a real "No surface at …" page; a missing client id shows "Client not found." Navigation has a 320ms route skeleton so it never flashes blank.
  • Built One decision store, one toast, one menu — single-owner stores (IX / FL / AS / LM / INT / ST / SG), usePPToast (role="status", portaled, ref-stable timer, Undo), and a MoreMenu with aria-haspopup/expanded + role="menu". No duplicated state anywhere.
  • Built Baseline interaction hygiene — bell popover is role="dialog" + Esc-to-close; / focuses page search (suppressed while typing); A/D/E, J/K, ⌘↵, ⌘K are wired; search inputs actually filter their lists; reduced-motion is honored on route/detail transitions.

01Missing surfaces — parity & funnel gaps

Five surfaces users had before or expect now. Each has a home in the current IA and a shared pattern to reuse — none needs new architecture.

U1Forms — top-of-funnel captureMissingP1

Lead-capture forms are the one on-ramp that creates leads; right now leads only arrive via the scripted inbound. Scope it thin: a field list, a live preview, and a submissions inbox that drops straight into leads/src:form.

Fold-in: Campaigns → Forms · Reuse: the Leads source-strip + drawer; a submission is just a lead with src: "form". Wires to: leads:arrived, source-strip tick — the plumbing you already built for Riley.

U2Knowledge base — what agents ground onMissingP1

Distinct from AI memory (learned rules): the documents, policies, and price lists agents cite. Studio's Compose already claims "inherits 5 workspace memories" — that link currently points at a memory pane, not a knowledge home.

Fold-in: Settings → AI memory gains a "Knowledge" section, or a sibling tab. Reuse: the memory provenance card (source, uses, impact) verbatim — a doc is a memory with a file attached.

U3Team — invites, roles, seatsBuiltP1

Settings → Workspace now has a real Team section on session state (ST_STORE): roster with Owner/Operator/Viewer roles, invite-by-email with seat accounting (4 of 5 seats), role changes and removal (both toast+undo, sole-owner guarded), a role-capability legend, and an owner-only View as switch that previews a lower role and gates this section's own controls. The ST_STORE.can(action) contract (approve / autonomy / disconnect / billing / team) is the foundation the app-wide gate below plugs into.

Shipped: role matrix + team:changed event. Next: apply can() to Approve / disconnect / top-up across surfaces (the §02 scenario).

U4Reviews & Referrals surfacePartialP2

Review Bot and Referral Engine exist as agents, and an "ob-referral" campaign is drafted — but there's no place to see review volume, star trend, or who-referred-whom. The pieces are scattered across Fleet, Outbound, and Store with no reader.

Fold-in: Campaigns → Reviews, run as an agent playbook (not a standalone tool). Reuse: Outbound campaign cards + Segments "advocates" list.

U5First-run / empty-workspace storyMissingP2

A brand-new workspace with zero agents, zero leads, zero history has no designed state — every surface assumes seeded data. For an "agent OS," the cold-start ("connect a channel → hire your first agent → watch it work") is the pitch and needs a path, not a tour overlay.

Fold-in: Today's brief becomes the guide when counts are zero. Reuse: the "No surface" / "queue clear" empty patterns already in the shell.

U6Ambient integration-health signalPartialP3

Integration health lives only inside Settings → Integrations and the Gmail-reauth Task. Legacy surfaced it ambiently; a topbar dot that turns amber when a channel degrades would make the existing INT_STORE visible everywhere.

Fold-in: topbar, beside the bell. Reuse: INT_STORE + integrations:changed — already firing, just not surfaced.

02Scenario coverage — the "what happens when…" matrix

The agent platform models failure richly (404 card · 401 scope · bad signature · quota cap · rejected listing). The core ops flows are still mostly happy-path. These are the states a real operator hits in week one.

03Minor nuances — the ship-readiness layer

Individually small, collectively the difference between a prototype and a product. Grouped so they can be swept in batches.

N1Focus management in overlaysPartial

Modals (Install, Ask, connect flow) autofocus their first field and close on Esc/backdrop — but Tab isn't trapped inside them and focus isn't returned to the trigger on close. One shared useFocusTrap + return-focus ref covers every overlay and is the biggest single a11y win.

N2Live-region announcementsPartial

Toasts announce via role="status", but count changes that matter — the Inbox "needs" badge, the bell unread count, a bulk "12 approved" — mutate silently. Add one polite aria-live region in the shell that the count events already firing can write into.

N3Copy correctness — plurals, time, moneyPartial

We already fixed one "1 installs" bug; sweep for the rest. Pluralize every counted noun, make relative times ("12m", "1h") derive from the seed clock consistently, keep currency/decimal formatting uniform (toLocaleString is used unevenly), and localize the booking timezone.

N4Mobile density on complex surfacesPartial

Off-canvas nav and swipe-to-close exist. Verify the dense surfaces below tablet: Studio's two-column connect flow and event trace, bulk action bars, wide tables (Reports, Pipeline board, Fleet roster) collapsing to cards, and the calendar week grid. Each needs a checked narrow layout, not just a reflow.

N5Deep-link & notification landing fidelityPartial

Entity routes resolve (verified in the regression sweep). Scenario-check the stale deep link: a bell item pointing at an already-decided thread, or a listing link after it's unlisted, should land gracefully (with context) rather than on a bare "decided" row. Reduced-motion coverage is also spotty — extend it past route/fleet transitions to the entrance animations.

N6Persistence boundary — say it out loudPartial

Session stores live in memory; a refresh resets decisions, installs, and the one-shot moments. That's correct for a demo, but "frontend complete" means the boundary is intentional: decide what would persist server-side (decisions, installs, prefs) vs what's session-only (scripted arrivals), and keep notification prefs / theme in localStorage as they already are.

04Recommended sequence

Unlock the widest surface first. U3 (Team/roles) is the keystone — it turns an entire scenario column (role-gated actions) from impossible to trivial, and it's a small store plus a settings section.

Then close the funnel. U1 (Forms) is the only thing that creates leads and reuses the Riley plumbing wholesale — high payoff, low cost.

  1. U3 Team/roles + N1 focus-trap — the keystone surface and the keystone a11y util; everything downstream leans on both.
  2. Scenario sweep §02 empties + partial-failure sends — the two states an operator hits fastest; both reuse existing patterns (empty cards, Tasks failed row).
  3. U1 Forms → U2 Knowledge — finish the funnel's top, then give agents their grounding home.
  4. N2/N3 copy + live-region sweep — a single mechanical pass across all pages (plurals, time, money, announcements).
  5. U4 Reviews · U5 first-run · U6 ambient health · N4 mobile — the differentiators and polish, once the parity floor is in.

Everything here hangs on stores and components that already exist. The frontend isn't waiting on new architecture — it's waiting on breadth of scenario and a nuance pass. Say which tier to start and I'll build it.
