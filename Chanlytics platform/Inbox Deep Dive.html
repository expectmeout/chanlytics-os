Inbox — the decision engine

Composition: list rail · thread pane · agent rail + decide engineFiles: inbox.jsx · inbox-list.jsx · inbox-thread.jsx · inbox-rail.jsx

Inbox is the system's beating heart — every committing verb (approve, decline, snooze, verdict, veto, take-over) lives or writes here. The engine is genuinely strong: snapshot-undo on everything, IX_STORE write-through, closed verbs, auto-advance, concurrent-change banners. The gaps are at the edges: two side surfaces that predate the policy machinery, and a handful of paths where the contracts don't quite reach.

01What it gets right

  • Every decision is a snapshot — decide/verdict/snooze/wake/archive/auto-send all capture prev state and offer working Undo through the shared toast queue.
  • Closed verbs honored — approve/edit/decline/snooze/take over, verdicts as their own gate, plan params as parameters (never new verbs), fallback stated on the card.
  • The hard scenarios exist — concurrent-change Refresh banner, veto countdowns with presence freeze, one-voice takeover, escalation without drafts, honest empty states per bucket.
  • Search spans buckets, saved views are real predicates, bulk bar follows the count·actions·flash·clear grammar.

02Gaps found

Seven, ranked. #1 and #2 are contract violations — #2 can break the agent charter.

1Train-the-agent bypasses the policy matrixCharterThe rail's "For decisions like this" segment speaks a retired vocabulary (auto | ask | stop), guesses the permission by regexing the approval kind, writes "stop" as ask (a mislabeled write), defaults to "ask" regardless of the live policy, and isn't role-gated. Worst: on Aisha's refund it happily saves Auto-approve for money decisions — the one thing the charter forbids. Rebuild on the rails: class from approval.policyClass, live mode from window.POLICY, money class renders the charter lock, writes go through POLICY.set (fires policy:changed), gate autonomy.
2Hotkey A drops the plan parameterContract"Approve records the pick" — the Approve button passes the chosen slot ("Thu 2:00") into the decision record and timeline, but the keyboard path calls decide() without it: same verb, different receipt. The param pick lives as local state in the thread pane where the engine can't see it. Lift it to the engine so A and the button write identical records.

Move the computation above the effect and fix the deps.

03Deliberately fine as-is

  • Save draft / Regenerate — session mocks with honest microcopy; no persistence pretense worth building.
  • Done baseline (+48 this week) — seeded archive depth, labeled in the empty state.
  • Auto-advance choosing by priority, not view order — deciding from a saved view advances to the highest-priority needs thread; defensible triage behavior.
  • Rail's canned "Ask the agent" answers — deterministic, cite real evidence, stay inside the thin-client rule.

Verdict. The engine is the best-built thing in the app; the drift is in the satellites. The rail's train-the-agent control is the one genuinely dangerous find — it predates the policy matrix and can write auto on a money class the charter locks. Everything else is edge-tightening: one lifted state, one effect fix, gate sweeps, deep links, two honest receipts.
