**In the harness every file's top-level names are one namespace.** Babel's env preset makes a top-level `const` a `var`, so it lands on `window` and the file loaded last decides it: the retired `pages/pipeline.jsx` once replaced `PipelineBoard` and broke the Pipeline's Board. A top-level name is unique across the tree, or the same thing in every file that declares it (hooks take a per-file alias: `useState: usePipeState`). `legacy-harness.test.mjs` runs every file in that one scope and fails a second meaning.

**The standalone harness is NOT the app, and never the evidence for a design change.** It loads every file over
`data/bridge-stubs.jsx`, so the surfaces the bridge feeds do not mount in it: Today, the real Calendar, People, Leads
and Live come out as a `soon` placeholder or the seeded mockup, on demo data at a density no workspace has. Use it for
the shell, the seeded pages, and to check a new file loads in both lists. To LOOK at a page you are changing, run the
dashboard and open `/w/<workspace-slug>/` -- docs/runbook.md, "See a real page", which names the three things that
trip it up. A screenshot of `Chanlytics.html` offered as proof of a real page will be sent back.

**A new file goes in BOTH lists.** Seventeen went into the manifest alone — each with its own test — and the harness booted to a blank page for however long that took to notice. `tooling/scripts/tests/legacy-harness.test.mjs` pins the two lists together now, in file order. Bump `?v=N` on every edited file; the harness's server sends `no-store` because the document itself has no version.

## Architecture
- **Data layer** (`data/*.jsx`): seed objects exported on `window.*`. No React. Files own their domain:
  - `clients-data` → CLIENTS, CLIENT_SEGMENTS, CLIENT_BUCKETS, CLIENTS_AGGREGATES
  - `people-data` → LEADS, LEAD_STAGES/SOURCES/AGGREGATES, SEGMENT_META, SEG_* (movement/health/guardrails), FLEET_PLAYBOOKS, lead segments (pushed into CLIENT_SEGMENTS — the sanctioned cross-file mutation; approved builder drafts use the same writeback via SG_STORE)
  - `inbox-data` → INBOX_*, THREADS, **IX_STORE** (session decision store)
  - `fleet-data` → FLEET_DATA (roster); `tasks-data` → TASKS_DATA; `dashboard-data` → AGENT_TASKS, ASK_*
- **Pages** own state; cross-surface state goes through IX_STORE or window events — never duplicated stores.

## Canonical enums (do not invent variants)
- Thread state: `needs | watching | drafts | escalated | snoozed | done`
- Task status: `pending | scheduled | running | done | failed`
- Lead stage (the mockup's, `people-data.jsx`): `ready | qualifying | new | nurture | converted | archived`. The real set is the stored one — `ready | nurture | converted | archived` with a `closed_reason` — and its words are contracts' `LEAD_STAGE_WORDS` (`packages/contracts/src/leads.ts`). The seeded set is never read by the Leads scope of People.
- Client bucket: `needs-you | drifting | champion | new | steady`
- Segment kind: `agent | manual | lead`; playbook status: `running | draft` (+ session-paused)
- Agent activity status: `in-flight | approval | escalated | scheduled | stalled`
- Store caps: `streams | interrupts | state | handoff | push` (plain-English labels via CAP_META; protocol names — A2A, AG-UI, agent card, event traces — appear ONLY inside Studio + a listing's provenance/Connection section); listing status: `submitted | listed | unlisted | rejected` (rejection = deterministic overclaim copy check; resubmit re-runs review)
- **Agent charter (domain rule)**: agents never decide money — no refunds, discounts, or negotiation; a money moment's plan is always "book a call with a human rep." Agent jobs: instant response (<1 min), FAQ answers from shared lead/client knowledge (list prices OK, exceptions never), book/reschedule/cancel + 15-min pre-call reminders, offer-free re-engagement of dormant leads. The booked call IS the conversion event.
- **Decision verbs (closed set, MVP-deterministic)**: `approve | edit | decline | snooze | take over` — payload is always `{threadId, verb, draftText?}`. Nuance (counters, credits, routing) lives in `approval.plan` (the ONE thing Approve executes: label/oneLine/$Δ/ltv/confidence/cta) + `fallback` (what Decline deterministically triggers) + read-only `alternatives`; `plan.param {label, options[{label, reply}]}` = deterministic parameters inside the plan (slot choice swaps the composer draft; Approve records the pick) — parameters, never new verbs. The pick is lifted to the Inbox engine (`planParams` map), so hotkey A and the Approve button write the SAME record; a decided thread's receipt cites `fallback` on Decline, `is executing` otherwise. Never invent new committing verbs; agents send a holding message ("checking with the owner — hear back within the hour") before escalating.
- **Verdict verbs (post-meeting, human-only)**: `deal | client | interested` — meeting end spawns a verdict thread (`thread.verdict`); unanswered 48h → auto-files interested, never deal. Deal/client write through to lead stage + `leads:verdict` (+`leads:converted` for client); deal also unshifts PIPELINE_DEALS `d-gabby` (undoable). The 48h deadman is a scheduled Tasks row (`t-verdict-timer`) that flips to done when the verdict lands.
- **Veto window (third autonomy mode)**: ask-first < veto-window < auto. `thread.veto {window,draft}` + VW_STORE countdown — auto-sends at 0 unless Edit/Hold/Take-over/typing cancels (VetoBar carries all three controls); eligibility = confidence ≥ 0.8 AND inside the agent envelope; takeover or a manual reply cancels the thread timer (one voice). `PR_STORE {away, transfers}` is the presence model — Away freezes every veto countdown at its current second (VW `frozen` ms, resumes on return), forces the holding line, and disables transfers; topbar presence menu owns it, Fleet phone agents show the live escalation path, Ask flips it ("set me away"). `window.transferGate()` gates Live controls. Policy matrix (Settings · Autonomy): action classes × auto|veto|ask|never, ST_STORE `"policy.<id>"`; money row locked by charter. Single source `window.POLICY` (data-bits) — Fleet Autonomy rows chip the mapped workspace mode (`POLICY.forPerm`), locked classes render the charter lock instead of tabs; `policy:changed` fires on set. Inbox cards + Command rows chip their class (`approval.policyClass` / `veto.policyClass` / `task.policyClass`) — locked → "Owner-only · Money", else "{chip} · {what the mode does}" ("Replies · holds it" — `POLICY.WORDS`, from contracts `POLICY_MODE_WORDS`; the stored modes stay auto|veto|ask|never and are never shown, #657), click → admin/autonomy. the Inbox rail's per-decision control ("For {chip} decisions like this") edits the mapped POLICY row DIRECTLY via `POLICY.set` (gated `autonomy`; money renders the charter lock, never tabs) — no separate FL_STORE writeback. ONE component: `PolicyChip cls=` (data-bits, self-updates on policy:changed) — also on Tasks rows, Outbound batches, Broadcasts composer, Calendar booked-via, Conversations summaries; Ask answers "what can agents do" live from POLICY. Trust digest: `RP_TRUST` (reports-data; byClass.reply mirrors RP_STATS auto) + `window.TRUST.cls/agent/rate` — surfaces: Reports header + per-agent Edit-rate column, Fleet Trust card (clean streak → milestone unlock), matrix row evidence lines, PolicyChip tooltips, VetoBar agent edit rate, Ask "edit rate" intent. Under 5% = widen-autonomy signal. 2+ live countdowns → Inbox sending-soon strip (Hold all); Today's rail shows its own strip at 1+ (VW_UTIL in inbox-data owns seed/remaining/holdAll + the presence freeze listener — pages only tick). Today fleet cards show the TRUST digest (edit rate/streak/milestone), never the retired 1–4 autonomy meter; HeroBrief "waiting" + Command's "+N more in Inbox" both count needs THREADS minus IX decisions (same math as the sidebar badge).
- Priority: `P1 | P2 | P3` — **data-only**: never rendered as chips; urgency shows as the accent left edge + sort order. Confidence renders as words (`Safe to send` ≥0.8 · `Wants your eyes` ≥0.5 · `Needs you`), never dots; tones: `pos | neg | warn` (+ empty = neutral)

## Numeric contracts
- Confidence is **0–1 float everywhere**. Thresholds: **SAFE ≥ 0.8** (bulk approve, high-conf views, 3 dots), MED ≥ 0.5. `dashboard-data` AGENT_TASKS 1–3 dot scale maps 3→safe. Never introduce 0.75 variants.
- Seed clock: "today" = **Apr 26, seed year**; session timestamp for new events = `12:04` (IX_NOW). Waiting urgency: amber past **30m**.
- IDs: clients `c-*`, leads `ld-*`, threads `th-*`, tasks `t-*`, conversations `cv-*`, appts `a-*`, segments kebab (`lapsed-60`), agents kebab of name (`phone-rep`).

Always deep-link the specific entity, never the generic page, when an id exists. Every view of Leads is one mount (app-shell.jsx `shellMountKey`), and `p-<lead>` is the lead open over the view, never part of what a read is keyed by: opening one pushes an entry, the cursor walking it on replaces it (`onNavigate(to, { replace: true })`), and Back closes it. The bridge holds the last eight views it read: a view seen before paints at once and is refreshed behind, a rail row under the pointer warms its view (`onWarm`), and a view on its way is said (`data-loading`, the table's `aria-busy`), never re-ordered locally: `leads_page`'s order is the one rule. ## UI patterns
- **Decisions**: any committing action → IX_STORE (if thread-linked) + `.pp-toast` with Undo (snapshot-restore). Toast is the shared pattern — no new flash variants. Render toasts via `usePPToast()` from data-bits (portals to <body>; stacks up to 3 with independent undo timers) — never a page-local `fn._t` timer.
- **Measure (how wide a surface may be)**: a page picks ONE of `--measure-prose` (720px — a column of rows, forms or sentences), `--measure-page` (1160px — lists and tables that need more than a column) or `--measure-wide` (1480px — a multi-column grid), with `--gutter-page` for its horizontal padding. A surface with its own panes (Inbox, Calendar, Fleet, People, Segments) takes none of them and is full-bleed by design; Reports is a `--measure-wide` column inside its own full-width scroller. Campaigns' three tabs take `--measure-wide` on the left, as Today does; Playbooks and Templates scroll in their own `.rp-body`, which stays as wide as the pane and keeps the measure as its right padding (`.rp-body.cm-page`), because a scroller capped at the measure draws its bar in the middle of a wide window. Never write a page max-width as a literal: the Setup rows had none at all, so they grew with the window while the cards above and below them stayed at 720, and the gap got worse the wider the monitor.
- **Charts** are one kit, shaped like shadcn's (`components/chart-*.jsx`: core, bar, line, pie, radar, radial, heat; `styles/charts.css`; Reports was its first page). A `config` names each series once (`{ key: { label, color, icon?, shape? } }`); the `ChartCard` a chart sits in publishes each colour as `--color-<key>` on its own `<section>`, draws the legend for two or more series, and owns the Chart/Table switch, the table twin (its own `table`, or one made from `twin: { data, keys, first }`) and a CSV spelled by `window.__csvCell` (contracts `csvCell`, never a second rule). A chart body paints only `var(--color-<key>)` and takes the same `config` for its words: no React context, because the node test stub renders children before their parents. The area is `LineChart` with a filled series; `SegmentBar` is one bar in its parts with its legend. Every chart is ONE tab stop (`role="group"`, the arrows walk it, a live region says each point), reads a touch as a mouse, draws at its measured width (600 until measured), and places its tooltip in pixels so it never leaves the card. The page places cards with its own classes; the kit knows no grid. Colours come only from charts.css's validated tokens: `--chart-1` for any single series, `--chart-cat-1..5` for channels in their fixed order (a channel keeps its colour whatever its rank), `--chart-ramp-1..5` for ordered things, `--chart-prior` for the period before; a status colour rides with an icon or a word, and the coral accent is never a data colour. Re-run the dataviz skill's `validate_palette.js` before changing a token. Reports itself is `pages/reports.jsx` (the shell, Google) and `pages/reports-sections.jsx` (everything the period scopes); every sentence beside a number there is the view model's (`vm.lines`, `cm.lines`, the booking's `words`, `__REPORTS.facts`). The standalone mockup draws the same page from `window.__reportsSample`, which `tooling/scripts/serve-legacy.mjs` builds from `legacy-bridge/reports-sample.ts`.
- **Today** is three bands in this order (`pages/dashboard-a.jsx`): a line only while a line is down or the workspace is paused (`dashboard-a-brief.jsx` HeroBrief draws `TodayAlert`, `today-alert`; the standing line with the date, the time and the lines counted went on 23 Sep), then the queue with the day beside it (`dashboard-a-command.jsx`, `dashboard-a-day.jsx`), with what is left to set up above the queue in its column, only while something is (read first after Today's own surface, and Today's first draw waits for it, `surface-registry.ts` ROUTE_DRAWS and ROUTE_WAITS, for at most ROUTE_WAIT_MS once Today's own surface is in, so it never lands above a queue already drawn; `dashboard-a-brief.jsx` TodaySetup, `today-setup`, canvas R10: the first run's one row while a step is open, Setup's own optional rows after with a Skip kept in the member's view, each drawn as the card's compact row, `setup.jsx` `SetupCardRow` through `SetupRows look="card"`; contracts `setupCardOf`), the day's card (`dashboard-a-brief.jsx` TodayCard: four figures from `TODAY_DATA.figures`, each with the clause under it and its receipt on hover, focus or a tap, then the lines that are not numbers, then `__today.periodLine` with the page's one door to Reports), then Worth a look and While you were away (`dashboard-a-week.jsx`). On a phone Ask is a full-screen takeover from the ✦ (`pages/ask-real.jsx`, spec `docs/superpowers/specs/2026-09-23-ask-the-stage-design.md`); Today draws no band. Ask's face is the top bar's button, the Stage's and the phone's ✦ (`tone="accent"`): `components/ask-face.jsx` AskFace following the one mood Ask says (`legacy-bridge/mascot/mood.ts`); the three's squares are alive on a canvas the bridge drives (`legacy-bridge/mascot`, published as `window.__mascot` and bundled for the mockup as `data/mascot.js`). Ask itself is the Stage (`pages/ask-real.jsx`: the three in a band at 84px, the answer on a rail of their squares, the same file as the phone's takeover; spec `docs/superpowers/specs/2026-09-23-ask-the-stage-design.md`). Every sentence with a number is contracts' (`today.ts`: `toTodayVM`, `todayDay`, `todayPeriodLine`, `todayRunWords`, `todayLeaks`, `todayAwayGrouped`, `todaySteps`, published as `window.__today` by `legacy-bridge/today.ts` `TODAY_HELPERS`); the page composes and never derives. The day panel opens with the steps due (0007, amended; `todaySteps`: three at most, the rest a line to People's Steps due), in every workspace, calendar or not: with no day to draw, the panel is the steps alone. A borrowed read that failed says so where its line would be (`FailedRead` with `window.__surfaceFailed`). The standalone mockup draws the same page from `legacy-bridge/today-sample.ts`, which `serve-legacy.mjs` builds as `data/today-sample.js` and which installs its surfaces only where the app's globals are absent. Never add a `readCode`/`readRaw` pin in a new Today test: `today-page.test.mjs` and `today-sample.test.mjs` execute the page and the sample on the stub React instead. A style for Today's copy of a shared row names Today's page, `:where(.dash-a-v2) .tq …`: `.tq`, the queue's card, is also the card the first run's rows sit in, and a row rule on `.tq` alone once hid every Setup glyph and folded each row's words into its 36px column.
- **One gutter per pane, owned by the parent**: a scrolling pane sets its own horizontal padding and separates children with `gap`; children never re-supply it as a margin. `.ix-th-scroll` had three children carrying it themselves and the rest carrying none, so a bordered alert sat flush against the dividers on both sides.
- **How things come and go** (components.css, "HOW THINGS COME AND GO"; data-bits `touchSwipe`, `leaving`): an overlay comes in the way it sits (a centred dialog rises a few pixels as it fades, a side sheet slides from its edge, a phone's sheet rises from the bottom, its wash fades) and leaves the same way, faster, on `--ease-in`, by a still copy React no longer holds: a new overlay takes `ref={window.leaving("<key>")}` on its sheet, with its wash as the sibling before it. On a phone every sheet, the lead's peek and Ask's palette are pulled down to close and an open thread swipes right to its list, following the finger (`touchSwipe({ onDown | onBack, when })`); the close is the page's own, so a page that asks first about what was typed still asks, and the sheet settles back to show the question. Keyframes move `translate`, `scale` and `opacity`, never `transform`, so a sheet centred by its transform, or held by a finger, keeps it. Nothing moves under reduced motion but the finger's own drag. No motion library: the shell has no bundler, and this is CSS and one helper.
- **A switch holds still** (data-bits `holdStill`): a tab, a filter or a fold that changes what is drawn beside it runs its change as `onClick={(e) => window.holdStill(e && e.currentTarget, change)}`. The change is drawn at once (`flushSync`); where it left the page too short to stay where it stood, the scroller is given the difference as padding at its foot (under everything, never between two things on the page) and put back, and that room gives itself back as the page is scrolled up until none is left; a control that moved anyway (what changed was above it) is scrolled back. On a phone the person's History tabs jumped 328px down the screen for Consent and 439px for Visits before it (23 Sep). Wired on the person's History filters and notes, the Pipeline's section folds, the Leads chips and bench groups, the Calendar's views and Hours and rules, a chart card's Chart/Table, Today's While you were away, and Connections' "Not right?". A fold that opens as a sheet on a phone keeps its row drawn behind it (`RecordFold behind`), so the card under the wash is the height it was.
- **A door is a link** (data-bits `routeDoor`): a name, a face or a chip with a page of its own is `<a {...window.routeDoor(to, go)}>`, its address in the href (a long press, a middle click or a new tab opens it) and the app's own way there on a plain press (`go`, else `CHANLY.nav`). Who a conversation is with is one such link in every header that names them (`inbox-thread.jsx` `IxWho`: the face, the name with a quiet chevron, and the line under it, in the thread's header and the call's in Conversations; Live's caller name, and their number as `tel:`); "Open profile" stays in the Actions menu. A step whose day has come sits under the thread's header, outside that link, with Done (`IxThreadStep`, 0007 amended): a button inside a link is not one.
- **Bulk bars**: count · actions · flash confirmation · clear; "Approve all safe" always means confidence ≥ 0.8.
- **Segment chips**: sparkle = smart, filter = saved, bolt = lead-list; always click → `segments/<id>` in the demo. On a real workspace the lists are a view of People: a smart list is `clients/seg:<id>`, a kept one `clients/list:<id>`, and `segments/<id>` lands there (app-shell asks `window.__listRoute`).
- **Role gates**: committing controls spread `{...window.gate("approve|autonomy|disconnect|billing|team|settings|export", "what this control does")}` AFTER their handlers in the opening tag. Denied → `aria-disabled`, `aria-description` and `data-tip` carrying contracts' sentence (refusal.ts `roleGate`, published as `window.__roleGate`), every acting handler replaced, and a press shows the reason at the control (`window.__tip.show`) — never `disabled` + `title`, which no keyboard or finger reaches. Allowed → no-op. A page's primary act is shown gated to a role that may not press it; an item's secondary acts (Edit, Delete, Rename, Pause, Skip) stay out of sight, and the page says why once with `window.gateTitle(perm, doing)`. ## Code conventions
- Unique hook aliases per file (`useLdState`, `useTkState`…); NEVER a bare global `styles` object; components shared via `Object.assign(window, {...})`.
- **The loading standard's kit: take it, never write a page's own.** Where the member was in a view (a box's words, the cursor, the scroll) and work half-done (a Find, a reply, a composer) go through `window.__tabMemory` (`legacy-bridge/tab-memory.ts`: `place`/`keepPlace`, `draft`/`keepDraft`/`dropDraft`): the tab's storage, per workspace, a page's last twelve views, a draft a day old forgotten, all of it gone at sign-out; guard with `window.__tabMemory &&`, since the standalone harness has none. People keeps `{ q, cursor, top }` per view (`all`, `seg:<id>`, `list:<id>`, `state:<tab>`) through the same hook Leads keeps its place with (`usePlPlace` in `clients-a.jsx`). A selection is never kept. A surface whose view the address or the page picks holds the views it read with `legacy-bridge/held-views.ts` (the last N, per workspace, and `ask()`/`still()` to drop a slow answer for a view already left), and publishes the view its rows ARE of, never one still on its way. A view on its way wears `data-loading` on its root and `aria-busy` on its list, and marks what dims with `data-dims` (`components.css`): what is on screen stays, never a blank or a skeleton over rows already there. A route whose surface has not landed yet is an empty pane that says `Reading…` after a beat (`app-shell.jsx`, the route view; `components.css` `.route-reading`), never a skeleton: the one that stood there matched no page and moved every page when it left. A pane shows the item asked for or says it is gone, never the list's first in its place (`|| visible[0]`). An act answers when the server takes it, never after the surfaces are read again: a page that shows the act on its rows at once passes `refresh: "behind"` (Leads, `actAtOnce`); a page the server repaints says so from the client's `onAccepted` and keeps the act its own until the re-read lands (the Inbox, Conversations and Today through `threadVerbs` and `inboxVerb`), and a reply's toast still waits for the receipt it carries. A reply half-written is kept per thread (`draft("reply", threadId)`), never the receptionist's own draft. A composer (the send screen, the playbook sheet, a template) keeps its words through the kit's one rule, `useUnsavedWork(kind, key, { value, dirty, onLeave })` in `record-fold.jsx`: kept in the tab as typed, back when the composer opens again (`tabDraft(kind, key)` as the page's state is made), gone when the server takes it (`done()`), the tab and Settings' rail held while it has words (the registry's `hold`), and its Cancel asks once (`leave` → `asking`, drawn as `UnsavedAsk`); a choice alone (a list, a message) is not words. The item open in a list beside its pane is the address's, written by the page as it opens (replaced, never pushed: Back leaves the page rather than replaying every item read), so a refresh opens it again and the crumbs name it (`inbox/<thread>`, `live/<call>`, `conversations/<tab>:<id>` — the row on its tab, `CV_ROUTE` reads it and `CV_ADDRESS` spells it; the words in its box are kept per tab); a page that follows its own address this way is one mount across it (app-shell.jsx `PARAM_FOLLOWED_AS_PROP`). A peek over a list is the exception that pushes (Leads' `:p-<lead>`, which Back closes).
- A page's saved view (`window.__saveView(page, view)`, `memberships.views`) is replaced whole on every save (`member_view_set`, 00113): send every key the page owns, each time, and one save at a time, because two in flight can land out of order (People's `plViewSaver`: the latest waits while one is out, and a failure is tried once more, unless a newer view is waiting). People's is `{ sortBy, sortDir, columns }`; a column put back to its default drops its key.
- The table (`PeopleTable` in `pages/people-table.jsx`, loaded before `clients-a.jsx`) takes its columns from whoever draws it — People's `PL_COLUMNS`, the Leads scope's own — and says what it calls its rows (`noun`: the foot's count, the select-all label, and the `id` the page's cursor effect looks up). The helpers beside it take the column list too (`plSortKeys`, `plDrawnColumns`, `plColumnChoices`, `plColumnOptions`). It and its Columns menu are hookless, their state the page's, where its one keyboard listener can close the menu and move the cursor. The table stays a `<table class="cl-table">`, so the page's selectors and the phone's card rules hold. Given `sections` it draws its rows in groups, each a `<tbody>` of its own under a head row that names it, counts it and says its meta, and a collapsed one as its head alone with its toggle; without them it is one body, as it always was.
- **People and Leads are two components over one list page** (`clients-a.jsx`): `PeopleReal` and `LeadsReal`, which the shell mounts apart (`shellMountKey`), each holding only its own state; the Pipeline is a third (`PipelineScope`, `pipeline-scope.jsx`), over the same two hooks, which `clients-a.jsx` publishes for it. Both take the list page from two hooks, in this order: `usePlControls` before the view works out its rows (the width, the toast, the selection, the saved sort and columns, the words in the box), and `usePlPlace` after (the cursor, each view's place, the first rows, and the one keyboard listener, which the view feeds on every draw with `keysWith`). A rule both scopes keep goes in one of the two hooks, never into both views. Every stub React the page tests draw on (`_legacy-react.mjs`, and each page test's own, but for three that draw one component and nothing under it) keeps each hook's state where its component sits, as React does (`tooling/scripts/tests/_hook-frames.mjs`), so a component drawn only some of the time moves nobody else's state, and throws as React does when a component's hooks change in number. Pages shaped to the old one-call-order rule (the Business tab's hookless rows and its last sheet slot) keep that shape as a habit; nothing new needs it.
- Layout: flex/grid + `gap`, no margin-sibling spacing. Data lookups: `(window.X || [])` fallbacks.
- Seed edits: anchor on unique `id:` lines; keep sums consistent (e.g. LEAD_SOURCES totals = LEADS_AGGREGATES).
