## Architecture
- **Data layer** (`data/*.jsx`): seed objects exported on `window.*`. No React. Files own their domain:
  - `clients-data` → CLIENTS, CLIENT_SEGMENTS, CLIENT_BUCKETS, CLIENTS_AGGREGATES
  - `people-data` → LEADS, LEAD_STAGES/SOURCES/AGGREGATES, SEGMENT_META, SEG_* (movement/health/guardrails), FLEET_PLAYBOOKS, lead segments (pushed into CLIENT_SEGMENTS — the sanctioned cross-file mutation; approved builder drafts use the same writeback via SG_STORE)
  - `inbox-data` → INBOX_*, THREADS, **IX_STORE** (session decision store)
  - `fleet-data` → FLEET_DATA (roster); `tasks-data` → TASKS_DATA; `dashboard-data` → AGENT_TASKS, ASK_*
- **Pages** own state; cross-surface state goes through IX_STORE or window events — never duplicated stores.

## Canonical enums (do not invent variants)
- Thread state: `needs | watching | drafts | escalated | snoozed | done`
- Task status: `pending | scheduled | running | done | failed`
- Lead stage (the mockup's, `people-data.jsx`): `ready | qualifying | new | nurture | converted | archived`. The real set is the stored one — `ready | nurture | converted | archived` with a `closed_reason` — and its words are contracts' `LEAD_STAGE_WORDS` (`packages/contracts/src/leads.ts`). The seeded set is never read by the Leads scope of People.
- Client bucket: `needs-you | drifting | champion | new | steady`
- Segment kind: `agent | manual | lead`; playbook status: `running | draft` (+ session-paused)
- Agent activity status: `in-flight | approval | escalated | scheduled | stalled`
- Store caps: `streams | interrupts | state | handoff | push` (plain-English labels via CAP_META; protocol names — A2A, AG-UI, agent card, event traces — appear ONLY inside Studio + a listing's provenance/Connection section); listing status: `submitted | listed | unlisted | rejected` (rejection = deterministic overclaim copy check; resubmit re-runs review)
- **Agent charter (domain rule)**: agents never decide money — no refunds, discounts, or negotiation; a money moment's plan is always "book a call with a human rep." Agent jobs: instant response (<1 min), FAQ answers from shared lead/client knowledge (list prices OK, exceptions never), book/reschedule/cancel + 15-min pre-call reminders, offer-free re-engagement of dormant leads. The booked call IS the conversion event.
- **Decision verbs (closed set, MVP-deterministic)**: `approve | edit | decline | snooze | take over` — payload is always `{threadId, verb, draftText?}`. Nuance (counters, credits, routing) lives in `approval.plan` (the ONE thing Approve executes: label/oneLine/$Δ/ltv/confidence/cta) + `fallback` (what Decline deterministically triggers) + read-only `alternatives`; `plan.param {label, options[{label, reply}]}` = deterministic parameters inside the plan (slot choice swaps the composer draft; Approve records the pick) — parameters, never new verbs. The pick is lifted to the Inbox engine (`planParams` map), so hotkey A and the Approve button write the SAME record; a decided thread's receipt cites `fallback` on Decline, `is executing` otherwise. Never invent new committing verbs; agents send a holding message ("checking with the owner — hear back within the hour") before escalating.
- **Verdict verbs (post-meeting, human-only)**: `deal | client | interested` — meeting end spawns a verdict thread (`thread.verdict`); unanswered 48h → auto-files interested, never deal. Deal/client write through to lead stage + `leads:verdict` (+`leads:converted` for client); deal also unshifts PIPELINE_DEALS `d-gabby` (undoable). The 48h deadman is a scheduled Tasks row (`t-verdict-timer`) that flips to done when the verdict lands.
- **Veto window (third autonomy mode)**: ask-first < veto-window < auto. `thread.veto {window,draft}` + VW_STORE countdown — auto-sends at 0 unless Edit/Hold/Take-over/typing cancels (VetoBar carries all three controls); eligibility = confidence ≥ 0.8 AND inside the agent envelope; takeover or a manual reply cancels the thread timer (one voice). `PR_STORE {away, transfers}` is the presence model — Away freezes every veto countdown at its current second (VW `frozen` ms, resumes on return), forces the holding line, and disables transfers; topbar presence menu owns it, Fleet phone agents show the live escalation path, Ask flips it ("set me away"). `window.transferGate()` gates Live controls. Policy matrix (Settings · Autonomy): action classes × auto|veto|ask|never, ST_STORE `"policy.<id>"`; money row locked by charter. Single source `window.POLICY` (data-bits) — Fleet Autonomy rows chip the mapped workspace mode (`POLICY.forPerm`), locked classes render the charter lock instead of tabs; `policy:changed` fires on set. Inbox cards + Command rows chip their class (`approval.policyClass` / `veto.policyClass` / `task.policyClass`) — locked → "Owner-only · Money", else "{chip} · {what the mode does}" ("Replies · holds it" — `POLICY.WORDS`, from contracts `POLICY_MODE_WORDS`; the stored modes stay auto|veto|ask|never and are never shown, #657), click → admin/autonomy. the Inbox rail's per-decision control ("For {chip} decisions like this") edits the mapped POLICY row DIRECTLY via `POLICY.set` (gated `autonomy`; money renders the charter lock, never tabs) — no separate FL_STORE writeback. ONE component: `PolicyChip cls=` (data-bits, self-updates on policy:changed) — also on Tasks rows, Outbound batches, Broadcasts composer, Calendar booked-via, Conversations summaries; Ask answers "what can agents do" live from POLICY. Trust digest: `RP_TRUST` (reports-data; byClass.reply mirrors RP_STATS auto) + `window.TRUST.cls/agent/rate` — surfaces: Reports header + per-agent Edit-rate column, Fleet Trust card (clean streak → milestone unlock), matrix row evidence lines, PolicyChip tooltips, VetoBar agent edit rate, Ask "edit rate" intent. Under 5% = widen-autonomy signal. 2+ live countdowns → Inbox sending-soon strip (Hold all); Today's rail shows its own strip at 1+ (VW_UTIL in inbox-data owns seed/remaining/holdAll + the presence freeze listener — pages only tick). Today fleet cards show the TRUST digest (edit rate/streak/milestone), never the retired 1–4 autonomy meter; HeroBrief "waiting" + Command's "+N more in Inbox" both count needs THREADS minus IX decisions (same math as the sidebar badge).
- Priority: `P1 | P2 | P3` — **data-only**: never rendered as chips; urgency shows as the accent left edge + sort order. Confidence renders as words (`Safe to send` ≥0.8 · `Wants your eyes` ≥0.5 · `Needs you`), never dots; tones: `pos | neg | warn` (+ empty = neutral)

## Numeric contracts
- Confidence is **0–1 float everywhere**. Thresholds: **SAFE ≥ 0.8** (bulk approve, high-conf views, 3 dots), MED ≥ 0.5. `dashboard-data` AGENT_TASKS 1–3 dot scale maps 3→safe. Never introduce 0.75 variants.
- Seed clock: "today" = **Apr 26, seed year**; session timestamp for new events = `12:04` (IX_NOW). Waiting urgency: amber past **30m**.
- IDs: clients `c-*`, leads `ld-*`, threads `th-*`, tasks `t-*`, conversations `cv-*`, appts `a-*`, segments kebab (`lapsed-60`), agents kebab of name (`phone-rep`).

## Routes (hash)
`today · inbox[/th-id] · clients[/c-id | /seg:seg-id | /leads[:s-<search>][:l-<list>][:c-<class>][:p-<lead>]] · segments[/seg-id] · store · studio · fleet[/agent-id] · outbound · content · broadcasts[/seg-id | /run:<broadcast-id>] · calendar[/a-id | /YYYY-MM-DD] · reports · tasks · conversations[/<tab> | /cv-id | /<tab>:<id>] · live · pipeline · admin/<pane>` (panes: workspace/autonomy/integrations/memory/notifications/billing). Always deep-link the specific entity, never the generic page, when an id exists. Every view of Leads is one mount (app-shell.jsx `shellMountKey`), and `p-<lead>` is the lead open over the view, never part of what a read is keyed by: opening one pushes an entry, the cursor walking it on replaces it (`onNavigate(to, { replace: true })`), and Back closes it. What belongs to a view follows `viewRoute` in `clients-a.jsx`, not `leadsRoute`; the page keeps each view's place (the box's words, the cursor, the map, the scroll) and a Find half-written in the tab's storage, which signing out clears with the surface cache. An act on a lead (Keep, Exclude, Put back, a stage, a bulk act by ids) shows on the row at once and answers when the door accepts, with the re-read behind it (`legacy-bridge/leads.ts` `actAtOnce`, `client/api.ts` `refresh: "behind"`); a refused act puts the row back. A cold boot reads the view the address names, in the order the tab last read it (`leadsBootView`), so the runner's first read is the page's own. The bridge holds the last eight views it read: a view seen before paints at once and is refreshed behind, a rail row under the pointer warms its view (`onWarm`), and a view on its way is said (`data-loading`, the table's `aria-busy`), never re-ordered locally: `leads_page`'s order is the one rule. Unbuilt surfaces fall through to `soon/<surface>`; unknown routes render NotFound. **Nav collapse**: the sidebar is 8 flat items (Today · Inbox · People · Calendar · Campaigns · Agents · Reports · Settings; Agents only in a demo, so 7 on a real workspace); merged surfaces (Inbox=inbox/conversations/live, People=clients/leads/pipeline/segments, Campaigns=outbound/broadcasts/messages/content, Agents=fleet/store/studio/tasks) navigate via `SurfaceTabs` (components/surface-tabs.jsx, shell-rendered) — ALL routes stay unchanged. The Inbox's strip reads Needs you · Conversations · Live (#655: inboxOverride and conversationsOverride read the same `GET conversations`, so they are views of one door, not two places); Campaigns' reads Playbooks · Broadcasts · Templates — the route is still `messages` (#658). On a phone the tab bar is Today · Inbox · Calendar · People · More (#660). Agent Command has Now/Soon only (Done = Tasks ledger).

## UI patterns
- **Decisions**: any committing action → IX_STORE (if thread-linked) + `.pp-toast` with Undo (snapshot-restore). Toast is the shared pattern — no new flash variants. Render toasts via `usePPToast()` from data-bits (portals to <body>; stacks up to 3 with independent undo timers) — never a page-local `fn._t` timer.
- **Measure (how wide a surface may be)**: a page picks ONE of `--measure-prose` (720px — a column of rows, forms or sentences), `--measure-page` (1160px — lists and tables that need more than a column) or `--measure-wide` (1480px — a multi-column grid), with `--gutter-page` for its horizontal padding. A surface with its own panes (Inbox, Calendar, Fleet, People, Segments) takes none of them and is full-bleed by design; Reports is a `--measure-wide` column inside its own full-width scroller. Never write a page max-width as a literal: the Setup rows had none at all, so they grew with the window while the cards above and below them stayed at 720, and the gap got worse the wider the monitor.
- **Charts** are one kit, shaped like shadcn's (`components/chart-*.jsx`: core, bar, line, pie, radar, radial, heat; `styles/charts.css`; Reports was its first page). A `config` names each series once (`{ key: { label, color, icon?, shape? } }`); the `ChartCard` a chart sits in publishes each colour as `--color-<key>` on its own `<section>`, draws the legend for two or more series, and owns the Chart/Table switch, the table twin (its own `table`, or one made from `twin: { data, keys, first }`) and a CSV spelled by `window.__csvCell` (contracts `csvCell`, never a second rule). A chart body paints only `var(--color-<key>)` and takes the same `config` for its words: no React context, because the node test stub renders children before their parents. The area is `LineChart` with a filled series; `SegmentBar` is one bar in its parts with its legend. Every chart is ONE tab stop (`role="group"`, the arrows walk it, a live region says each point), reads a touch as a mouse, draws at its measured width (600 until measured), and places its tooltip in pixels so it never leaves the card. The page places cards with its own classes; the kit knows no grid. Colours come only from charts.css's validated tokens: `--chart-1` for any single series, `--chart-cat-1..5` for channels in their fixed order (a channel keeps its colour whatever its rank), `--chart-ramp-1..5` for ordered things, `--chart-prior` for the period before; a status colour rides with an icon or a word, and the coral accent is never a data colour. Re-run the dataviz skill's `validate_palette.js` before changing a token. Reports itself is `pages/reports.jsx` (the shell, Google) and `pages/reports-sections.jsx` (everything the period scopes); every sentence beside a number there is the view model's (`vm.lines`, `cm.lines`, the booking's `words`, `__REPORTS.facts`). The standalone mockup draws the same page from `window.__reportsSample`, which `tooling/scripts/serve-legacy.mjs` builds from `legacy-bridge/reports-sample.ts`.
- **Today** is three bands in this order (`pages/dashboard-a.jsx`): a line only while a line is down or the workspace is paused (`dashboard-a-brief.jsx` HeroBrief draws `TodayAlert`, `today-alert`; the standing line with the date, the time and the lines counted went on 23 Sep), on a phone only, the three (`today-face.jsx` TodayFace, above the core; always the full face, the field slides in when a tap wakes it and a press held listens, `data-open`; at 721px and up the band is not drawn and Ask's face is the top bar's button and the palette's stage, `components/ask-face.jsx` AskFace following the one mood the palette and the band say, `legacy-bridge/mascot/mood.ts`; on a phone the ✦ is the three too, `tone="accent"`; spec 4.7, 4.8), then the queue with the day beside it (the three's squares are alive on a canvas the bridge drives, `legacy-bridge/mascot`, published as `window.__mascot` and bundled for the mockup as `data/mascot.js`; the band asks through `window.__ask` on a thread of its own, quick answers first, and hands an answer with a proposal to the palette with `askAbout({ thread })`; spec `docs/superpowers/specs/2026-09-23-the-three-on-today-design.md`), the queue with the day beside it (`dashboard-a-command.jsx`, `dashboard-a-day.jsx`), the day's card (`dashboard-a-brief.jsx` TodayCard: four figures from `TODAY_DATA.figures`, each with the clause under it and its receipt on hover, focus or a tap, then the lines that are not numbers, then `__today.periodLine` with the page's one door to Reports), then Worth a look and While you were away (`dashboard-a-week.jsx`). Every sentence with a number is contracts' (`today.ts`: `toTodayVM`, `todayDay`, `todayPeriodLine`, `todayRunWords`, `todayLeaks`, `todayAwayGrouped`, published as `window.__today` by `legacy-bridge/today.ts` `TODAY_HELPERS`); the page composes and never derives. A borrowed read that failed says so where its line would be (`FailedRead` with `window.__surfaceFailed`). The standalone mockup draws the same page from `legacy-bridge/today-sample.ts`, which `serve-legacy.mjs` builds as `data/today-sample.js` and which installs its surfaces only where the app's globals are absent. Never add a `readCode`/`readRaw` pin in a new Today test: `today-page.test.mjs` and `today-sample.test.mjs` execute the page and the sample on the stub React instead. A style for Today's copy of a shared row names Today's page, `:where(.dash-a-v2) .tq …`: `.tq`, the queue's card, is also the card Setup's rows sit in, and a row rule on `.tq` alone once hid every Setup glyph and folded each row's words into its 36px column.
- **One gutter per pane, owned by the parent**: a scrolling pane sets its own horizontal padding and separates children with `gap`; children never re-supply it as a margin. `.ix-th-scroll` had three children carrying it themselves and the rest carrying none, so a bordered alert sat flush against the dividers on both sides.
- **How things come and go** (components.css, "HOW THINGS COME AND GO"; data-bits `touchSwipe`, `leaving`): an overlay comes in the way it sits (a centred dialog rises a few pixels as it fades, a side sheet slides from its edge, a phone's sheet rises from the bottom, its wash fades) and leaves the same way, faster, on `--ease-in`, by a still copy React no longer holds: a new overlay takes `ref={window.leaving("<key>")}` on its sheet, with its wash as the sibling before it. On a phone every sheet, the lead's peek and Ask's palette are pulled down to close and an open thread swipes right to its list, following the finger (`touchSwipe({ onDown | onBack, when })`); the close is the page's own, so a page that asks first about what was typed still asks, and the sheet settles back to show the question. Keyframes move `translate`, `scale` and `opacity`, never `transform`, so a sheet centred by its transform, or held by a finger, keeps it. Nothing moves under reduced motion but the finger's own drag. No motion library: the shell has no bundler, and this is CSS and one helper.
- **Bulk bars**: count · actions · flash confirmation · clear; "Approve all safe" always means confidence ≥ 0.8.
- **Segment chips**: sparkle = smart, filter = saved, bolt = lead-list; always click → `segments/<id>` in the demo. On a real workspace the lists are a view of People: a smart list is `clients/seg:<id>`, a kept one `clients/list:<id>`, and `segments/<id>` lands there (app-shell asks `window.__listRoute`).
- **Role gates**: committing controls spread `{...window.gate("approve|autonomy|disconnect|billing|team|settings|export", "what this control does")}` AFTER their handlers in the opening tag. Denied → `aria-disabled`, `aria-description` and `data-tip` carrying contracts' sentence (refusal.ts `roleGate`, published as `window.__roleGate`), every acting handler replaced, and a press shows the reason at the control (`window.__tip.show`) — never `disabled` + `title`, which no keyboard or finger reaches. Allowed → no-op. A page's primary act is shown gated to a role that may not press it; an item's secondary acts (Edit, Delete, Rename, Pause, Skip) stay out of sight, and the page says why once with `window.gateTitle(perm, doing)`. Engine fns double-guard with `window.canDo(action)` so hotkeys/bulk paths respect roles. `AttnRow` takes `cta.gate`/`also.gate`, `MoreMenu` items take `gate` and its trigger `gated={sentence|null}`, `SetSeg` and `EmptyState` actions take `gate`. Defined in data-bits; role source `ST_STORE.myRole()` incl. View-as.
- Pills via `.pill pill-{accent|ok|warn|danger}`; per-domain pills (TkPill, BucketPill) wrap these, never restyle (`LeadStagePill` went with the seeded Leads page).
- **Badges: one shape per job** (docs/superpowers/specs/2026-09-23-one-badge-system-design.md; the shapes live once in components.css, "Badges: one shape per job"). A state is the pill (`StatePill`): filled in its tone's soft ground and ink for what asks to be seen (warn, info, danger, and accent with its live dot), and a 6px dot with the word for a state at rest (ok, plain), so a filled ground always means "look here". A name (a list, a person, a role, a service, a source, a policy) is `.chip`: 20px, a hairline, no fill, never a tone; its buttons sit inside it, the × is `.chip-x`. A number on a tab, a nav row, a filter or an icon is `.tally` (16px), `tally-warn` when it counts people who need you, `tally-icon` on a glyph; a rail's bare numbers keep `.count`. A row's kind is `.mark` (24px, radius 6, sunken, never toned: the row's pill or words carry the tone). One size each: a page adds the class and keeps only its layout, never its own size. "Needs you" is amber on every badge and in every sentence; red is for what failed; the coral accent is for live and "now" only, never a count or a label; tone words take the `-ink` token, never the raw tone.
- **People on a phone** (900px and under, `PL_PHONE_QUERY`; docs/superpowers/specs/2026-09-22-people-on-a-phone-design.md): one bar for both scopes (`PeoplePhoneBar` in clients-a.jsx: the People | Leads switch, the list shown, search behind a button that opens a 16px field, and People's more-menu or Leads' Find), the standing line, then the rows. A person's row is one cell (`plCardCell`, `PL_PHONE_COLUMNS`, `tr.pl-card-row`): face, name and state; why they need a person or their own words; the next visit and the last contact. The face is the checkbox, and while anyone is selected a tap on a row selects it; More › Select people starts a selection with nobody picked (`selectMode`, `PeopleTable selectMode`). A selection is one docked row on both scopes (`.cl-bulk.pp-bulk`: ✕, the count, one act and ⋯), and ⋯ is a sheet of `PhoneSheetRow`s where an act that asks something first asks it as a step (`onBack`); the step is the page's `bulkSheet`, and `clearSelection` is the one way a selection ends (it lets go of Leads' "all N that match" too). People's small jobs (Add a person, a list's rename, delete and "Save these") open as sheets (`PhoneSheet`), hookless, drawn last, closed on Esc by the page's one listener. The desktop's controls row and list head are not drawn on a phone.
- **One row for every list on a phone** (900px and under): People's row, the Inbox's, Conversations' and a lead's each had their own numbers — measured on production at 375px, 22 Sep: 84px, 83, 100 and 131, with two name sizes, three gutters, two faces and a 56px photograph between them. `tokens.css` holds the row once (`--row-pad-y`/`--row-pad-x`, `--row-face`, `--row-gap`, `--row-line-gap`, `--row-name-line`, `--row-said-line`, `--row-facts`, `--row-facts-line`) and every sheet reads it: a 32px face at a 16px gutter, then who it is and how it stands, what was said, and the facts under them. **A sheet never restates the numbers.** What a list puts on the three lines is still its own — the Inbox keeps its channel, its wait and its agent; a lead keeps its reach and its rating. A pill is words, not a control, and `legacy-bridge/legacy.css` puts no touch floor on it (it used to give every `.pill` 36px, which made a row taller than a person's, and every row undid it); a pressed chip keeps its 20px look and grows an invisible target instead. A phone ignores the Inbox's compact/rich density: that is a desktop's choice of how much fits. **Above 900px nothing is shared** — a rail beside an open thread is not a list you scan with a thumb, so `.ix-thread`, `.cv-row` and `.lm-row` keep their own grids there. `e2e/phone.spec.ts` holds the four lists to one row.
- **A call in progress** is the shell's own bar ABOVE the status line (topbar.jsx `LiveCallBar`, words from contracts `liveBar`): who is on the phone and for how long, and a press opens Live. It carries no controls — handing over and ending ask before they act, on Live. Whether a call is still up between refreshes is contracts' `liveStillUp`, for every reader (the bar, the Live page, the strip's pulse).
- **The shell's status**: one line under the top bar (topbar.jsx `ShellStatusBar`; which state, its words and its one press from contracts `shellStatusLine`) says the device is offline, the receptionist paused, a newer build ready, a surface not refreshing, or live updates not coming through: one at a time, on every screen size. Pages don't repeat it. The tab's name is the crumbs, most particular first (`pageTitle`), so a crumb on a real workspace never carries a seeded name; the shell keeps it (`__shell.keepTitle`), because the layout's own title can land after it on a page loaded cold.
- Opening a thread (click, j/k, or Review) clears its unread dot; ⋯ · Mark as unread sets it back (toast, no Ask detour) — unread means unread, not "seeded unread". Cross-surface links deep-link the entity (rail "Open agent" → `R.agent`), never the generic page — except a lead, which has no page of its own: `R.lead()` answers `clients/leads`, the scope of People, and the demo's "Also in Leads" chip still says the lead's LIVE stage. Keyboard: ⌘K opens Ask (global, shell-owned) · `/` focuses page search · A/D/E on approvals · J/K or ↑/↓ walk the thread list · ⌘↵ send. The Inbox rows are a listbox (inbox-list.jsx): one tab stop, on the open row; arrows, J/K, Home and End open and focus the row on screen; Enter opens; Space selects for a bulk act, which runs once over its threads (`__inboxBulk`, one re-read at its end) and says its count and its refusals in one toast. People's rows take J/K or ↑/↓ (the row cursor), x or Space (select), Enter (open), `/` (search) and Esc (the Columns menu first, then the selection) from ONE listener registered for the page's life that reads a keys ref, as the Calendar's does (`clients-a.jsx`, `calendar-real.jsx`); a keydown listener added again on every render is what it replaced. It judges a key by where it was pressed (`e.target`), not where focus is by then, leaves one an earlier listener took (`e.defaultPrevented`), and holds still while anything else is open over the page: the phone's lists sheet, which closes on its own Esc listener (`PeopleListsSheet`), and any other menu or dialog in `.app-root`, the bulk bar's menus included (`PL_OVERLAY`; the phone's drawer is a dialog while open). The `?` sheet lists these keys (contracts `SHORTCUTS`). Suppress single-key shortcuts while typing (a row's checkbox is not typing). The cursor's row is the table's tab stop (`tabIndex` 0, the rest −1) and takes focus as the cursor moves, so a screen reader says it; a row focused by Tab or a click becomes the cursor (`onFocus` → `onCursor`). A heading that sorts is a `<button class="cl-th-sort">` inside its `<th>`, which keeps `aria-sort`. A selection's CSV spells each cell with `window.__csvCell` (contracts `csvCell`, the route's export's rule).
- **A person's page is one quiet record** (`pages/client-profile.jsx`, canvas A of 23 Sep): one scroll at Today's `--measure-wide`, on the left as Today is (it stood centred at `--measure-page`), never two panes, and a flex item that fills the shell's row (`flex: 1 1 auto; min-width: 0`, as `.clients` and `.inbox` do; it was 304px short at 1667). The head is who they are, where they stand (a dot and the standing's word beside the name, `person-now`, its `rightNow.detail` on hover, and said under the line only when the tone is not `answering`) and the page's acts beside them: the thread, its one primary, and a **More** menu whose items, words, groups and roles are contracts' `personActs` (`vm.acts`: Send booking link or proposal · Call, Copy number, Copy email · the owner's Delete person…), a few words each with a line between groups; what an act does is its hover (`title`), never a sentence beside the label, which wrapped and ran past the menu's edge. Opening a person is as quick as the tab can make it: People's rows read the person as a pointer reaches them or the cursor lands (`ctx.onWarm` → `__warmPerson`), and a person not read yet opens on their People row with `Reading…` after the standard's beat (`person-known`), never a bare Loading…. Their visits that have not ended are Coming up (contracts `comingUp`, each a door to its day), above History, which is the timeline without them (`ahead`). The card of what is known sits beside them on a desktop and between Coming up and History on a phone (`@container person`, 880px). What the card changes about them is the record kit's rows (`person-settings`: Receptionist, Visit messages, Offers & news, and Deal where deals are a thing, 0004), one line each at rest, and Change opens each one's editor in a `RecordFold` under the row (a sheet on a phone); these save as they are chosen, so their folds are given no `onSave` and draw only Close, and a recorded answer closes its fold. **Notes are a log** (docs/decisions/0007-person-notes.md, 00157): `PersonNotes` draws `vm.noteList` (contracts `personNotesVM`: the receptionist's suggestions first, then newest first, each with who, when, who it is for and Team only) under a one-line composer whose For and Team only appear once something is typed; its author edits a note, its author or an owner deletes it (asked inline, never a dialog), a suggestion takes Keep or Dismiss, and every write goes through `window.__personNotes` (write, remove, decide, with contracts' `NOTE_WORDS`) and re-reads the person. The receptionist reads only kept notes that are not Team only; a note's acts wait behind a ⋯ that escapes the card.
- **A proposal is a link on the person** (00154; docs/superpowers/specs/2026-09-22-proposal-link-design.md): the About row is its control (`PersonProposal` in client-profile.jsx, PersonEmail's shape, the host as the link with the whole address on hover), the head's acts send it beside the booking link (`send-proposal`, or the two as one Send menu, `person-send`; its words from contracts `proposalAction`, the message from `proposalMessage` through `window.__proposalMessage`, drawn only where free text can go and never for someone who opted out), and the thread's Actions menu fills the composer with it (`inbox:compose`). Never a file, never a figure the receptionist states; "Sent" is derived from the thread's own messages, not stored.

## Code conventions
- Unique hook aliases per file (`useLdState`, `useTkState`…); NEVER a bare global `styles` object; components shared via `Object.assign(window, {...})`.
- **The loading standard's kit: take it, never write a page's own.** Where the member was in a view (a box's words, the cursor, the scroll) and work half-done (a Find, a reply, a composer) go through `window.__tabMemory` (`legacy-bridge/tab-memory.ts`: `place`/`keepPlace`, `draft`/`keepDraft`/`dropDraft`): the tab's storage, per workspace, a page's last twelve views, a draft a day old forgotten, all of it gone at sign-out; guard with `window.__tabMemory &&`, since the standalone harness has none. People keeps `{ q, cursor, top }` per view (`all`, `seg:<id>`, `list:<id>`, `state:<tab>`) through the same hook Leads keeps its place with (`usePlPlace` in `clients-a.jsx`). A selection is never kept. A surface whose view the address or the page picks holds the views it read with `legacy-bridge/held-views.ts` (the last N, per workspace, and `ask()`/`still()` to drop a slow answer for a view already left), and publishes the view its rows ARE of, never one still on its way. A view on its way wears `data-loading` on its root and `aria-busy` on its list, and marks what dims with `data-dims` (`components.css`): what is on screen stays, never a blank or a skeleton over rows already there. A route whose surface has not landed yet is an empty pane that says `Reading…` after a beat (`app-shell.jsx`, the route view; `components.css` `.route-reading`), never a skeleton: the one that stood there matched no page and moved every page when it left. A pane shows the item asked for or says it is gone, never the list's first in its place (`|| visible[0]`). An act answers when the server takes it, never after the surfaces are read again: a page that shows the act on its rows at once passes `refresh: "behind"` (Leads, `actAtOnce`); a page the server repaints says so from the client's `onAccepted` and keeps the act its own until the re-read lands (the Inbox, Conversations and Today through `threadVerbs` and `inboxVerb`), and a reply's toast still waits for the receipt it carries. A reply half-written is kept per thread (`draft("reply", threadId)`), never the receptionist's own draft. A composer (the send screen, the playbook sheet, a template) keeps its words through the kit's one rule, `useUnsavedWork(kind, key, { value, dirty, onLeave })` in `record-fold.jsx`: kept in the tab as typed, back when the composer opens again (`tabDraft(kind, key)` as the page's state is made), gone when the server takes it (`done()`), the tab and Settings' rail held while it has words (the registry's `hold`), and its Cancel asks once (`leave` → `asking`, drawn as `UnsavedAsk`); a choice alone (a list, a message) is not words. The item open in a list beside its pane is the address's, written by the page as it opens (replaced, never pushed: Back leaves the page rather than replaying every item read), so a refresh opens it again and the crumbs name it (`inbox/<thread>`, `live/<call>`, `conversations/<tab>:<id>` — the row on its tab, `CV_ROUTE` reads it and `CV_ADDRESS` spells it; the words in its box are kept per tab); a page that follows its own address this way is one mount across it (app-shell.jsx `PARAM_FOLLOWED_AS_PROP`). A peek over a list is the exception that pushes (Leads' `:p-<lead>`, which Back closes).
- A page's saved view (`window.__saveView(page, view)`, `memberships.views`) is replaced whole on every save (`member_view_set`, 00113): send every key the page owns, each time, and one save at a time, because two in flight can land out of order (People's `plViewSaver`: the latest waits while one is out, and a failure is tried once more, unless a newer view is waiting). People's is `{ sortBy, sortDir, columns }`; a column put back to its default drops its key.
- The table (`PeopleTable` in `pages/people-table.jsx`, loaded before `clients-a.jsx`) takes its columns from whoever draws it — People's `PL_COLUMNS`, the Leads scope's own — and says what it calls its rows (`noun`: the foot's count, the select-all label, and the `id` the page's cursor effect looks up). The helpers beside it take the column list too (`plSortKeys`, `plDrawnColumns`, `plColumnChoices`, `plColumnOptions`). It and its Columns menu are hookless, their state the page's, where its one keyboard listener can close the menu and move the cursor. The table stays a `<table class="cl-table">`, so the page's selectors and the phone's card rules hold.
- **People and Leads are two components over one list page** (`clients-a.jsx`): `PeopleReal` and `LeadsReal`, which the shell mounts apart (`shellMountKey`), each holding only its own state. Both take the list page from two hooks, in this order: `usePlControls` before the view works out its rows (the width, the toast, the selection, the saved sort and columns, the words in the box), and `usePlPlace` after (the cursor, each view's place, the first rows, and the one keyboard listener, which the view feeds on every draw with `keysWith`). A rule both scopes keep goes in one of the two hooks, never into both views. Every stub React the page tests draw on (`_legacy-react.mjs`, and each page test's own, but for three that draw one component and nothing under it) keeps each hook's state where its component sits, as React does (`tooling/scripts/tests/_hook-frames.mjs`), so a component drawn only some of the time moves nobody else's state, and throws as React does when a component's hooks change in number. Pages shaped to the old one-call-order rule (the Business tab's hookless rows and its last sheet slot) keep that shape as a habit; nothing new needs it.
- Layout: flex/grid + `gap`, no margin-sibling spacing. Data lookups: `(window.X || [])` fallbacks.
- Seed edits: anchor on unique `id:` lines; keep sums consistent (e.g. LEAD_SOURCES totals = LEADS_AGGREGATES).
