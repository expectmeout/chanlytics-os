# Chanlytics — Code Contracts & Conventions

> **Status, 11 September 2026.** This tree is the signed-in operator shell, bridged to real data by `src/legacy-bridge`
> (see `surface-registry.ts` for which surfaces are real). The mockup-only surfaces — Agents (fleet, store, studio,
> tasks), Content, Pipeline and Leads, the shared report viewer — stay here and stay hidden from every real workspace.
> Ruben's decision: most of it is revisited when the product is at 100%; none of those features is built before then.
> Nothing below this line is a plan to build them.

Single-page React (Babel, no bundler). `Chanlytics.html` loads: tokens/css → data/*.jsx → components/*.jsx → pages/*.jsx → app-shell. Bump `?v=N` on every edited file.

## Architecture
- **Data layer** (`data/*.jsx`): seed objects exported on `window.*`. No React. Files own their domain:
  - `clients-data` → CLIENTS, CLIENT_SEGMENTS, CLIENT_BUCKETS, CLIENTS_AGGREGATES
  - `people-data` → LEADS, LEAD_STAGES/SOURCES/AGGREGATES, SEGMENT_META, SEG_* (movement/health/guardrails), FLEET_PLAYBOOKS, lead segments (pushed into CLIENT_SEGMENTS — the sanctioned cross-file mutation; approved builder drafts use the same writeback via SG_STORE)
  - `inbox-data` → INBOX_*, THREADS, **IX_STORE** (session decision store)
  - `fleet-data` → FLEET_DATA (roster); `tasks-data` → TASKS_DATA; `dashboard-data` → AGENT_TASKS, ASK_*
- **Pages** own state; cross-surface state goes through IX_STORE or window events — never duplicated stores.

## Canonical enums (do not invent variants)
- Thread state: `needs | watching | drafts | escalated | snoozed | done`
- Task status: `pending | scheduled | running | done | failed`
- Lead stage: `ready | qualifying | new | nurture | converted | archived`
- Client bucket: `needs-you | drifting | champion | new | steady`
- Segment kind: `agent | manual | lead`; playbook status: `running | draft` (+ session-paused)
- Agent activity status: `in-flight | approval | escalated | scheduled | stalled`
- Store caps: `streams | interrupts | state | handoff | push` (plain-English labels via CAP_META; protocol names — A2A, AG-UI, agent card, event traces — appear ONLY inside Studio + a listing's provenance/Connection section); listing status: `submitted | listed | unlisted | rejected` (rejection = deterministic overclaim copy check; resubmit re-runs review)
- **Agent charter (domain rule)**: agents never decide money — no refunds, discounts, or negotiation; a money moment's plan is always "book a call with a human rep." Agent jobs: instant response (<1 min), FAQ answers from shared lead/client knowledge (list prices OK, exceptions never), book/reschedule/cancel + 15-min pre-call reminders, offer-free re-engagement of dormant leads. The booked call IS the conversion event.
- **Decision verbs (closed set, MVP-deterministic)**: `approve | edit | decline | snooze | take over` — payload is always `{threadId, verb, draftText?}`. Nuance (counters, credits, routing) lives in `approval.plan` (the ONE thing Approve executes: label/oneLine/$Δ/ltv/confidence/cta) + `fallback` (what Decline deterministically triggers) + read-only `alternatives`; `plan.param {label, options[{label, reply}]}` = deterministic parameters inside the plan (slot choice swaps the composer draft; Approve records the pick) — parameters, never new verbs. The pick is lifted to the Inbox engine (`planParams` map), so hotkey A and the Approve button write the SAME record; a decided thread's receipt cites `fallback` on Decline, `is executing` otherwise. Never invent new committing verbs; agents send a holding message ("checking with the owner — hear back within the hour") before escalating.
- **Verdict verbs (post-meeting, human-only)**: `deal | client | interested` — meeting end spawns a verdict thread (`thread.verdict`); unanswered 48h → auto-files interested, never deal. Deal/client write through to lead stage + `leads:verdict` (+`leads:converted` for client); deal also unshifts PIPELINE_DEALS `d-gabby` (undoable). The 48h deadman is a scheduled Tasks row (`t-verdict-timer`) that flips to done when the verdict lands.
- **Veto window (third autonomy mode)**: ask-first < veto-window < auto. `thread.veto {window,draft}` + VW_STORE countdown — auto-sends at 0 unless Edit/Hold/Take-over/typing cancels (VetoBar carries all three controls); eligibility = confidence ≥ 0.8 AND inside the agent envelope; takeover or a manual reply cancels the thread timer (one voice). `PR_STORE {away, transfers}` is the presence model — Away freezes every veto countdown at its current second (VW `frozen` ms, resumes on return), forces the holding line, and disables transfers; topbar presence menu owns it, Fleet phone agents show the live escalation path, Ask flips it ("set me away"). `window.transferGate()` gates Live controls. Policy matrix (Settings · Autonomy): action classes × auto|veto|ask|never, ST_STORE `"policy.<id>"`; money row locked by charter. Single source `window.POLICY` (data-bits) — Fleet Autonomy rows chip the mapped workspace mode (`POLICY.forPerm`), locked classes render the charter lock instead of tabs; `policy:changed` fires on set. Inbox cards + Command rows chip their class (`approval.policyClass` / `veto.policyClass` / `task.policyClass`) — locked → "Owner-only · Money", else "{chip} · {mode}", click → admin/autonomy. the Inbox rail's per-decision control ("For {chip} decisions like this") edits the mapped POLICY row DIRECTLY via `POLICY.set` (gated `autonomy`; money renders the charter lock, never tabs) — no separate FL_STORE writeback. ONE component: `PolicyChip cls=` (data-bits, self-updates on policy:changed) — also on Tasks rows, Outbound batches, Broadcasts composer, Calendar booked-via, Conversations summaries; Ask answers "what can agents do" live from POLICY. Trust digest: `RP_TRUST` (reports-data; byClass.reply mirrors RP_STATS auto) + `window.TRUST.cls/agent/rate` — surfaces: Reports header + per-agent Edit-rate column, Fleet Trust card (clean streak → milestone unlock), matrix row evidence lines, PolicyChip tooltips, VetoBar agent edit rate, Ask "edit rate" intent. Under 5% = widen-autonomy signal. 2+ live countdowns → Inbox sending-soon strip (Hold all); Today's rail shows its own strip at 1+ (VW_UTIL in inbox-data owns seed/remaining/holdAll + the presence freeze listener — pages only tick). Today fleet cards show the TRUST digest (edit rate/streak/milestone), never the retired 1–4 autonomy meter; HeroBrief "waiting" + Command's "+N more in Inbox" both count needs THREADS minus IX decisions (same math as the sidebar badge).
- Priority: `P1 | P2 | P3` — **data-only**: never rendered as chips; urgency shows as the accent left edge + sort order. Confidence renders as words (`Safe to send` ≥0.8 · `Wants your eyes` ≥0.5 · `Needs you`), never dots; tones: `pos | neg | warn` (+ empty = neutral)

## Numeric contracts
- Confidence is **0–1 float everywhere**. Thresholds: **SAFE ≥ 0.8** (bulk approve, high-conf views, 3 dots), MED ≥ 0.5. `dashboard-data` AGENT_TASKS 1–3 dot scale maps 3→safe. Never introduce 0.75 variants.
- Seed clock: "today" = **Apr 26, seed year**; session timestamp for new events = `12:04` (IX_NOW). Waiting urgency: amber past **30m**.
- IDs: clients `c-*`, leads `ld-*`, threads `th-*`, tasks `t-*`, conversations `cv-*`, appts `a-*`, segments kebab (`lapsed-60`), agents kebab of name (`phone-rep`).

## Routes (hash)
`today · inbox[/th-id] · clients[/c-id | /seg:seg-id] · leads[/src:source-id | /ld-id] · segments[/seg-id] · store · studio · fleet[/agent-id] · outbound · content · broadcasts[/seg-id] · calendar[/a-id] · reports · tasks · conversations[/phone|chats|mail | /cv-id] · live · pipeline · admin/<pane>` (panes: workspace/autonomy/integrations/memory/notifications/billing). Always deep-link the specific entity, never the generic page, when an id exists. Unbuilt surfaces fall through to `soon/<surface>`; unknown routes render NotFound. **Nav collapse**: the sidebar is 9 flat items (Today · Inbox · People · Conversations · Calendar · Campaigns · Agents · Reports · Settings); merged surfaces (People=clients/leads/pipeline/segments, Conversations=+live, Campaigns=outbound/broadcasts/content, Agents=fleet/store/studio/tasks) navigate via `SurfaceTabs` (components/surface-tabs.jsx, shell-rendered) — ALL routes stay unchanged. Agent Command has Now/Soon only (Done = Tasks ledger).

## Window contracts
- Globals: `appNavigate(route)`, `askAbout({prompt, answer?, links?, mode})`, `IX_STORE.set/clear/get(threadId)`, `FL_STORE.setPerm/getPerms/setStatus/statusOf/setPbPaused/isPbPaused` (fleet session overrides), `LM_STORE.end/isEnded` (live-call endings), `LD_STORE.arrive/arrived` (scripted inbound-lead arrival — fires once ~18s in; `leads:arrived {leadId,phase: arrived|scored}`), `INT_STORE.fix/isFixed` (integration health), `ST_STORE.set/get` (autonomy defaults) + `ST_STORE.getTeam/addMember/setRole/removeMember/can(action)/myRole/setViewAs` (team roster + role gating: owner⊃operator⊃viewer; owner can preview lower roles), `BC_HISTORY_SEED` (broadcasts push session sends so Segments detail sees them), `AS_STORE.install/uninstall/isInstalled/addToFleet/listings/addListing/setListingStatus` (agent platform: session installs + published listings; every install/connect/publish pushes a real FLEET_ROSTER entry — the fleet write-through).
- **Guardrail rail**: `SEG_GUARDRAILS` (people-data) is the one segId→rule matrix; it renders identically (`.fl-guard-link` shield chip → `admin/autonomy`) on Fleet playbooks, Segments detail rules row, the Broadcasts composer audience line, and Outbound segment-backed cards — all four re-render on `guardrails:changed`. Segments · Assign agent writes a REAL draft playbook into `FLEET_PLAYBOOKS[agentId]` + fires `fleet:playbooks {agentId,pbId,added}`; usage rows persist in `SG_STORE.usage`.
- Events: `inbox:counts {needs}` · `inbox:decisions` · `inbox:focus-composer` · `segments:new` · `ask:seed` · `fleet:perms {agentId,permId,value}` · `fleet:status {agentId,status}` · `fleet:playbooks {agentId,pbId,paused}` · `fleet:handoff {agentId,kind,route}` (scripted handoff ~14s after a studio-connected agent joins the fleet — bell + Tasks pending row + roster write-through) · `live:ended {callId,cvId}` · `guardrails:changed {segId,value}` · `integrations:changed {id}` · `billing:changed {topup}` · `store:installed {agentId}` · `store:listing {id}` · `team:changed` · `leads:converted {leadId,clientId}` · `leads:verdict {leadId,verdict}` · `presence:changed {transfers}` · `broadcasts:sent {segId,count,channel}` · `outbound:approved {id,count}` (the last three exist for bell pushes — every flow has a live notification moment).
- **Compliance rail**: `window.COMPLIANCE` registry (clients-data; absent = consented + clear, only exceptions recorded) + `CHANLY.compliance(id)/canMessage(id)`. Broadcasts subtracts non-messageable segment members ("held back — no consent/DNC"); Outbound batches carry `audience.held`; client profile About shows the Consent row; lead detail shows a Consent fact for exceptions; Outbound running campaigns subtract held members from segment audiences; Ask answers "can we message X"; Segments member preview counts held members; Broadcasts held note lists names on hover and scheduled sends subtract held at send time. Backend swap = one field per contact.
- Guard style: `window.appNavigate && window.appNavigate(...)` (safe no-op).

## UI patterns
- **Decisions**: any committing action → IX_STORE (if thread-linked) + `.pp-toast` with Undo (snapshot-restore). Toast is the shared pattern — no new flash variants. Render toasts via `usePPToast()` from data-bits (portals to <body>; stacks up to 3 with independent undo timers) — never a page-local `fn._t` timer.
- **Measure (how wide a surface may be)**: a page picks ONE of `--measure-prose` (720px — a column of rows, forms or sentences), `--measure-page` (1160px — lists and tables that need more than a column) or `--measure-wide` (1480px — a multi-column grid), with `--gutter-page` for its horizontal padding. A surface with its own panes (Inbox, Calendar, Reports, Fleet, People, Segments) takes none of them and is full-bleed by design. Never write a page max-width as a literal: the Setup rows had none at all, so they grew with the window while the cards above and below them stayed at 720, and the gap got worse the wider the monitor.
- **One gutter per pane, owned by the parent**: a scrolling pane sets its own horizontal padding and separates children with `gap`; children never re-supply it as a margin. `.ix-th-scroll` had three children carrying it themselves and the rest carrying none, so a bordered alert sat flush against the dividers on both sides.
- **Bulk bars**: count · actions · flash confirmation · clear; "Approve all safe" always means confidence ≥ 0.8.
- **Segment chips**: sparkle = smart, filter = saved, bolt = lead-list; always click → `segments/<id>`.
- **Role gates**: committing controls spread `{...window.gate("approve|autonomy|disconnect|billing|team")}` AFTER onClick in the opening tag (denied → disabled + reason tooltip + handler stripped; allowed → no-op). Engine fns double-guard with `window.canDo(action)` so hotkeys/bulk paths respect roles. MoreMenu takes `gated={title|null}`. Defined in data-bits; role source `ST_STORE.myRole()` incl. View-as.
- Pills via `.pill pill-{accent|ok|warn|danger}`; per-domain pills (TkPill, LeadStagePill, BucketPill) wrap these, never restyle.
- Opening a thread (click, j/k, or Review) clears its unread dot; ⋯ · Mark as unread sets it back (toast, no Ask detour) — unread means unread, not "seeded unread". Cross-surface links deep-link the entity ("Also in Leads" → `R.lead(leadId)` with the lead's LIVE stage; rail "Open agent" → `R.agent`), never the generic page. Keyboard: ⌘K opens Ask (global, shell-owned) · `/` focuses page search · A/D/E on approvals · J/K or ↑/↓ walk the thread list · ⌘↵ send. Suppress single-key shortcuts while typing.

## Code conventions
- Unique hook aliases per file (`useLdState`, `useTkState`…); NEVER a bare global `styles` object; components shared via `Object.assign(window, {...})`.
- Layout: flex/grid + `gap`, no margin-sibling spacing. Data lookups: `(window.X || [])` fallbacks.
- Seed edits: anchor on unique `id:` lines; keep sums consistent (e.g. LEAD_SOURCES totals = LEADS_AGGREGATES).
