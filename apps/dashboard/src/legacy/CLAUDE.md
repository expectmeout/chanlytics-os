**A new file goes in the app's list for it, and nowhere else:** `manifest.ts`; a stylesheet in `legacy.css`. ## Canonical enums (do not invent variants)
- Thread state: `needs | watching | drafts | escalated | snoozed | done`
- Task status: `pending | scheduled | running | done | failed`
- Lead stage (the mockup's, `people-data.jsx`): `ready | qualifying | new | nurture | converted | archived`. The real set is the stored one — `ready | nurture | converted | archived` with a `closed_reason` — and its words are contracts' `LEAD_STAGE_WORDS` (`packages/contracts/src/leads/leads.ts`). The seeded set is never read by the Leads scope of People.
- Client bucket: `needs-you | drifting | champion | new | steady`
- Segment kind: `agent | manual | lead`; playbook status: `running | draft` (+ session-paused)
- Agent activity status: `in-flight | approval | escalated | scheduled | stalled`
- Store caps: `streams | interrupts | state | handoff | push` (plain-English labels via CAP_META; protocol names — A2A, AG-UI, agent card, event traces — appear ONLY inside Studio + a listing's provenance/Connection section); listing status: `submitted | listed | unlisted | rejected` (rejection = deterministic overclaim copy check; resubmit re-runs review)
- **Agent charter (domain rule)**: agents never decide money — no refunds, discounts, or negotiation; a money moment's plan is always "book a call with a human rep." Agent jobs: instant response (<1 min), FAQ answers from shared lead/client knowledge (list prices OK, exceptions never), book/reschedule/cancel + 15-min pre-call reminders, offer-free re-engagement of dormant leads. The booked call IS the conversion event.
- **Decision verbs (closed set, MVP-deterministic)**: `approve | edit | decline | snooze | take over` — payload is always `{threadId, verb, draftText?}`. Nuance (counters, credits, routing) lives in `approval.plan` (the ONE thing Approve executes: label/oneLine/$Δ/ltv/confidence/cta) + `fallback` (what Decline deterministically triggers) + read-only `alternatives`; `plan.param {label, options[{label, reply}]}` = deterministic parameters inside the plan (slot choice swaps the composer draft; Approve records the pick) — parameters, never new verbs. The pick is lifted to the Inbox engine (`planParams` map), so hotkey A and the Approve button write the SAME record; a decided thread's receipt cites `fallback` on Decline, `is executing` otherwise. Never invent new committing verbs; agents send a holding message ("checking with the owner — hear back within the hour") before escalating.
- **Verdict verbs (post-meeting, human-only)**: `deal | client | interested` — meeting end spawns a verdict thread (`thread.verdict`); unanswered 48h → auto-files interested, never deal. Deal/client write through to lead stage (+ `leads:converted` for client); deal also unshifts PIPELINE_DEALS `d-gabby` (undoable). The 48h deadman is a scheduled Tasks row (`t-verdict-timer`) that flips to done when the verdict lands.
- **Veto window (third autonomy mode)**: ask-first < veto-window < auto. `thread.veto {window,draft}` + VW_STORE countdown — auto-sends at 0 unless Edit/Hold/Take-over/typing cancels (VetoBar carries all three controls); eligibility = confidence ≥ 0.8 AND inside the agent envelope; takeover or a manual reply cancels the thread timer (one voice). `PR_STORE {away, transfers}` is the presence model — Away freezes every veto countdown at its current second (VW `frozen` ms, resumes on return), forces the holding line, and disables transfers; topbar presence menu owns it, Fleet phone agents show the live escalation path, Ask flips it ("set me away"). Policy matrix (Settings · Autonomy): action classes × auto|veto|ask|never, ST_STORE `"policy.<id>"`; money row locked by charter. Single source `window.POLICY` (legacy-bridge/policy-store.ts) — Fleet Autonomy rows chip the mapped workspace mode (`POLICY.forPerm`), locked classes render the charter lock instead of tabs; `policy:changed` fires on set. Inbox cards + Command rows chip their class (`approval.policyClass` / `veto.policyClass` / `task.policyClass`) — locked → "Owner-only · Money", else "{chip} · {what the mode does}" ("Replies · holds it" — `POLICY.WORDS`, from contracts `POLICY_MODE_WORDS`; the stored modes stay auto|veto|ask|never and are never shown, #657), click → admin/autonomy. the Inbox rail's per-decision control ("For {chip} decisions like this") edits the mapped POLICY row DIRECTLY via `POLICY.set` (gated `autonomy`; money renders the charter lock, never tabs) — no separate FL_STORE writeback. ONE component: `PolicyChip cls=` (the kit's, `../surfaces/kit/house/policy-chip.tsx`, self-updates on policy:changed) — also on Tasks rows, Outbound batches, Broadcasts composer, Calendar booked-via, Conversations summaries; Ask answers "what can agents do" live from POLICY. Trust digest: `RP_TRUST` (reports-data; byClass.reply mirrors RP_STATS auto) + `window.TRUST.cls/agent/rate` — surfaces: Reports header + per-agent Edit-rate column, Fleet Trust card (clean streak → milestone unlock), matrix row evidence lines, PolicyChip tooltips, VetoBar agent edit rate, Ask "edit rate" intent. Under 5% = widen-autonomy signal. 2+ live countdowns → Inbox sending-soon strip (Hold all); Today's rail shows its own strip at 1+ (VW_UTIL in `src/surfaces/inbox/store.ts` owns seed/remaining/holdAll + the presence freeze listener — pages only tick). Today fleet cards show the TRUST digest (edit rate/streak/milestone), never the retired 1–4 autonomy meter; HeroBrief "waiting" + Command's "+N more in Inbox" both count needs THREADS minus IX decisions (same math as the sidebar badge).
- Priority: `P1 | P2 | P3` — **data-only**: never rendered as chips; urgency shows as the accent left edge + sort order. Confidence renders as words (`Safe to send` ≥0.8 · `Wants your eyes` ≥0.5 · `Needs you`), never dots; tones: `pos | neg | warn` (+ empty = neutral)

## Numeric contracts
- Confidence is **0–1 float everywhere**. Thresholds: **SAFE ≥ 0.8** (bulk approve, high-conf views, 3 dots), MED ≥ 0.5. `dashboard-data` AGENT_TASKS 1–3 dot scale maps 3→safe. Never introduce 0.75 variants.
- Seed clock: "today" = **Apr 26, seed year**; session timestamp for new events = `12:04` (IX_NOW). Waiting urgency: amber past **30m**.
- IDs: clients `c-*`, leads `ld-*`, threads `th-*`, tasks `t-*`, conversations `cv-*`, appts `a-*`, segments kebab (`lapsed-60`), agents kebab of name (`phone-rep`).

## Routes
A route is the path after the workspace's slug, `/w/<slug>/<route>`, and the frame stays mounted across a move (decision 0015, "The address first"). `/w/<slug>#/<route>`, which emails, the phone app's links and every bookmark say, is moved to its path when the frame loads and works for ever. A page reads and moves the address through `window.CHANLY.address` (`route()`, `href(route)`, `go(route, { replace, quiet })`, `hear(fn)`: `../surfaces/frame/constants.ts`, the bridge's in the app, `legacy-bridge/workspace.ts`, and over the hash in the standalone mockup), never through `window.location`; a new file does not go in this tree at all (`baselines/legacy-files.json`). The words below write a route without its slash or its `#/`:
`today · inbox[/th-id] · clients[/c-id | /seg:seg-id | /leads[:s-<search>][:l-<list>][:c-<class>][:p-<lead>] | /pipeline] · segments[/seg-id] · store · studio · fleet[/agent-id] · outbound · content · broadcasts[/seg-id | /run:<broadcast-id>] · calendar[/a-id | /YYYY-MM-DD] · reports[/<lens>][:<from>~<to>] · tasks · conversations[/<tab> | /cv-id | /<tab>:<id>] · live · pipeline · start[/business | /phone | /try | /live] · admin/<pane>` (panes: workspace/autonomy/integrations/memory/notifications/billing). **A route that has left the shell is an App Router page, and the table has no row for it**: Reports, the Calendar, People (`clients`, at `/w/<slug>/people`: the list and its views, its Leads scope, the Pipeline, a person's page), Lists (`segments`, at `/w/<slug>/lists`) and the first run (`start`, at `/w/<slug>/start`), through `surfaces/routes.ts` (`takes`, `chrome`). **The router is a route table**, `surfaces/frame/route-table.tsx` `SHELL_ROUTES`: one row per route (its page, which addresses of it the row takes, and a draw naming its component, crumbs, nav item, pane and primary act), first match wins, read by `../surfaces/frame/app-shell.tsx`'s `ChanlyticsApp` through `drawRoute`, which applies the honesty gate (`useRouteGate` in `../surfaces/frame/shell-hooks.ts`, the one gate) to every row's answer; a new route is a row there and a line in `surface-registry.ts`, never a branch in the shell. `start` is the first run, whose page the frame draws without its chrome; `admin/setup` moved there (surface-registry `ROUTES_MOVED`), because bell rows written before carry it. Always deep-link the specific entity, never the generic page, when an id exists. Every view of Leads is one mount (People's chrome names `clients/leads` for each, `surfaces/people/chrome.ts`, and the page follows its address as a prop, `surfaces/leads/page/leads-real.tsx`), and `p-<lead>` is the lead open over the view, never part of what a read is keyed by: opening one pushes an entry, the cursor walking it on replaces it (`onNavigate(to, { replace: true })`, the address's own replace: the shell's `CHANLY.nav` takes a route alone), and Back closes it. What belongs to a view follows `viewRoute` (`surfaces/leads/page/state.ts`), not the address; the page keeps each view's place (the box's words, the cursor, the map, the scroll) in the tab's storage, which signing out clears with the surface cache. **Find leads is Ask on the Leads surface** (docs/superpowers/specs/2026-09-24-ask-is-the-finder-design.md): the controls row's button, the F key and the first day's door open the Line as ⌘K does (the takeover on a phone, from the shell's ✦), with "Describe the businesses you want" in the field, the words sent as typed with `surface: "leads"`, and Ask's `lead_search` card commits and lands on the search. The page keeps only `LeadPlanPanel` (`surfaces/leads/finder/plan-panel.tsx`): the card for a plan born from the strip's next steps or a kept search's "Search again, changed", and the answer row under a search's question, which runs the amend turn (`leadAnswerPlan`, surface `leads`); a sheet on a phone (`LeadPlanSheet`, `.pl-plan`, the name `PL_OVERLAY` leaves the page's keys awake behind); no composer, no mic, no suggestions and no draft of its own (Ask keeps its own). An act on a lead (Keep, Exclude, Put back, a stage, a bulk act by ids) shows on the row at once and answers when the door accepts, with the re-read behind it (`legacy-bridge/leads.ts` `actAtOnce`, `client/api.ts` `refresh: "behind"`); a refused act puts the row back. A cold boot reads the view the address names, in the order the tab last read it (`leadsBootView`), so the runner's first read is the page's own. The bridge holds the last eight views it read: a view seen before paints at once and is refreshed behind, a rail row under the pointer warms its view (`onWarm`), and a view on its way is said (`data-loading`, the table's `aria-busy`), never re-ordered locally: `leads_page`'s order is the one rule. Unbuilt surfaces fall through to `soon/<surface>`; unknown routes render NotFound. **Nav collapse**: the sidebar is 8 flat items (Today · Inbox · People · Calendar · Campaigns · Agents · Reports · Settings; Agents only in a demo, so 7 on a real workspace); merged surfaces (Inbox=inbox/conversations/live, People=clients/leads/pipeline/segments, Agents=fleet/store/studio/tasks) navigate via `SurfaceTabs` (surfaces/frame/surface-tabs.tsx, shell-rendered) — ALL routes stay unchanged. Every strip of views is the kit's one (`ViewTabs`, `../surfaces/kit/view-tabs/`, the kit's `.stabs`: links, the highlight a change carries, and the press that starts the page leaving), which the frame draws through `SurfaceTabs`, over the page and never by it: from the group a route is in (`ST_GROUPS`), or from what the page's chrome says of its own views (`views`, `SurfaceViews` in `surfaces/routes.ts`; People's scopes People | Leads | Pipeline are `surfaces/people/chrome.ts`'s, with no strip of their own on the page, so they stand, glide, warm and swipe as the Inbox's do); Reports' lenses are `surfaces/reports/chrome.ts`'s, from the lens registry, drawn the same way, and a page sets only the strip's sides, and on a phone those are the rows' 16px (`e2e/shell/phone.spec.ts` holds the Inbox's and People's strips to one; Settings opens on a list of its sections on a phone, `settings/frame/list.tsx`). A change of view moves by one deck, the same on a desk and a phone and for a tap, a click, a key and a swipe (`../surfaces/kit/motion/view-deck.ts`, spec `docs/superpowers/specs/2026-10-08-one-motion-for-every-strip-design.md`): the page leaving and the page arriving are on one timeline, begun at the press or where the finger let go and at its speed; the one leaving never waits for React, the one arriving joins where it should already be, and the node React took away is put back as a still copy until it has left. A view is an element that is replaced when the view changes (the frame's `main`, Reports' lens body, Settings' pane): it registers with `viewDeck.view(owner)` and says which side it arrives from with `data-slide` (`stripPlace` and `stripSlide` for the frame's strips, the kit's `useSlide` for a page's own). How far it travels is the token `--view-travel`: its own width where a page is one column, a short length on a desk, where the two cross-fade. On a phone a swipe across the page walks the strip over it (`../surfaces/frame/surface-tabs.tsx` `stripSwipe` on the shell's route view, spec `docs/superpowers/specs/2026-09-25-swipe-between-tabs-design.md`): `touchSwipe` reads the touch and the kit's `viewPager` says what a page is; the page and the highlight follow the thumb, and let go past a third the tab beside is pressed, so a swipe is a tap. It never starts in a field, a row that scrolls across, a dialog, sheet, menu or toast, or anything marked `data-own-drag` (the Leads map, Live's hold-to-talk): mark whatever takes its own touch. The Inbox's strip reads Needs you · Conversations · Live (#655: inboxOverride and conversationsOverride read the same `GET conversations`, so they are views of one door, not two places); Campaigns has no strip since 3 Oct 2026: it is one page, its home (`campaigns`, `../surfaces/campaigns/home/`, canvas A "Lifecycle": the rail of moments, who can hear you, coming up, what came back; a moment or the composer opens in the kit's sheet at `campaigns/moment:<id>` and `campaigns/new`), and Sent (`broadcasts`) and the Library (`messages`, the path's `templates`) are rooms reached from it, their crumbs `Campaigns › Sent` and `Campaigns › Library`; the old Playbooks list, `outbound[/<id>]`, lands on Sequences for ever (contracts `retiredRouteOf`, the one table of retired addresses). On a phone the tab bar is Today · Inbox · Calendar · People · More (#660). Agent Command has Now/Soon only (Done = Tasks ledger).

## UI patterns
- **Decisions**: any committing action → IX_STORE (if thread-linked) + `.pp-toast` with Undo (snapshot-restore). Toast is the shared pattern — no new flash variants. Render toasts via `usePPToast()` from surfaces/frame/flash.tsx (portals to <body>; stacks up to 3 with independent undo timers) — never a page-local `fn._t` timer.
- **Measure (how wide a surface may be)**: a page picks ONE of `--measure-prose` (720px — a column of rows, forms or sentences), `--measure-page` (1160px — lists and tables that need more than a column) or `--measure-wide` (1480px — a multi-column grid), with `--gutter-page` for its horizontal padding. A surface with its own panes (Inbox, Calendar, Fleet, People, Segments) takes none of them and is full-bleed by design; Reports is a `--measure-wide` column inside its own full-width scroller. Campaigns' home, Sent and the Library take `--measure-wide` on the left, as Today does (`.cmh`, `.bc-page`, `.cm-page`); a scroller of their own would keep the measure as its right padding and stand as wide as the pane, because one capped at the measure draws its bar in the middle of a wide window. Never write a page max-width as a literal: the Setup rows had none at all, so they grew with the window while the cards above and below them stayed at 720, and the gap got worse the wider the monitor.
- **Charts** are one kit, shaped like shadcn's, and part of the interface kit since Reports left the shell (`../surfaces/kit/charts/`: card, bar, line, radar, radial, heat; `styles/charts.css`; Reports was its first page). A `config` names each series once (`{ key: { label, color, icon?, shape? } }`); the `ChartCard` a chart sits in publishes each colour as `--color-<key>` on its own `<section>`, draws the legend for two or more series, and owns the Chart/Table switch, the table twin (its own `table`, or one made from `twin: { data, keys, first }`) and a CSV spelled by `window.__csvCell` (contracts `csvCell`, never a second rule). A chart body paints only `var(--color-<key>)` and takes the same `config` for its words: no React context, because the node test stub renders children before their parents. ## Code conventions
- Unique hook aliases per file (`useLdState`, `useTkState`…); NEVER a bare global `styles` object; components shared via `Object.assign(window, {...})`.
- No object rest (`({ a, ...rest }) =>`, `const { a, ...rest } = x`): the harness's Babel keeps its excluded keys in a top-level `var _excluded`, the harness runs every file in one scope, and the file loaded last decides what every other file's rest leaves out. Write out the props an element is given instead (`window.propsWithout` once took the rest and was taken down unread, 11 October 2026). `legacy-harness.test.mjs` fails a second file with one.
- **The loading standard's kit: take it, never write a page's own.** Where the member was in a view (a box's words, the cursor, the scroll) and work half-done (Ask's field, a reply, a composer) go through `window.__tabMemory` (`legacy-bridge/tab-memory.ts`: `place`/`keepPlace`, `draft`/`keepDraft`/`dropDraft`): the tab's storage, per workspace, a page's last twelve views, a draft a day old forgotten, all of it gone at sign-out; guard with `window.__tabMemory &&`, since the standalone harness has none. People keeps `{ q, cursor, top }` per view (`all`, `seg:<id>`, `list:<id>`, `state:<tab>` for the states that are not lists: Needs you and Waiting on you open as `seg:`) through the same hook Leads keeps its place with (`usePlPlace` in `people.jsx`). A selection is never kept.
